# ADR-0041: 委譲の上限を andon コマンドから外し、オーナーが前もって任せた PR をオーナーを待たずにマージする

- 日付: 2026-11-21
- 出典: ADR-0041（[adr/0041-delegation-cap-out-of-command.md](../adr/0041-delegation-cap-out-of-command.md)。Chief Engineer の課題。オーナーが対話の中で決めた。元はオーナーの発言 2026-11-21「語を置き換えるだけの PR は自動マージの範囲に入れていい」「andon コマンドが、プロジェクトについて強く認識しているのは違和感がある」）
- 覆す: [decisions.md](../decisions.md) の設計書 §6 問い 26 の答えのうち「Andon 自身のパッケージが常にオーナー」（一部。固定の決まりから、オーナーが委譲で広げられる既定に変える）と、設計書 §6 問い 7 の答えのうち「Andon の repo はレベル C のまま」（一部。Andon を開発するセルの、下げたパスについて）と、ADR-0028 のやらないこと「Andon のパッケージに触れる改善の PR の自動マージ」（一部）と、ADR-0039 決めたこと 9 の「`AGENTS.md`・テンプレート・モデルの規則は C のまま」（一部）と、ADR-0025 決めたこと 8 の「規則を弱める変更はオーナーが見る」（一部。同じセルの上書きが効く間）

`andon delegate` は、プロジェクトを名前で見分けて委譲の上限を決めない。Andon 自身のプロジェクトも、ほかのプロジェクトと同じ決まりで委譲を読み書きする。今ある `project.json` の型と値は変わらず、Andon を開発するセルは、今までどおりレベル B までが自動である。gate の追加行のパターンは、当たる箇所がその hunk で増えたときだけレベル C の理由にし、増えていなければレベル B の理由にする。語の置き換えだけの PR かどうかは機械で見分けず、オーナーが課題を名指しして `merge` を委譲する口（`andon delegate grant merge <値> --issues <id,…>`）を足す。名指しは gate が回る前に出し、担当が戻せないと申告した PR には効かない。Andon を開発するセルでは、バージョンが v0.0.x の間、repo の直下の `AGENTS.md`・`package/environment.md`・`package/writing.md`・テンプレート・モデルの規則と控えと対応表に触れる PR のレベルを、セルの条件表の上書きで B に下げる。中身・理由・捨てた案は ADR が正。
