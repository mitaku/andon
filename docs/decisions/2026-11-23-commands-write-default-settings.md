# command が足す担当の課題とルーチンが足した課題は、予約キーを既定で持って起動できる

- 日付: 2026-11-23
- 出典: Chief of Staff の依頼（2026-11-23）。トリアージの apply が足した直す課題・ルーチンが足したトリアージ・その直す課題が、予約キーの無いまま `andon issue start` に断られ、同じ日に3回 Chief of Staff が手で書いた
- 覆す: [decisions/2026-11-22-issue-start-refuses-unset-settings.md](2026-11-22-issue-start-refuses-unset-settings.md) の「コマンドは値を決めず、何も書かない」（ルーチンが足した課題に限る）

- 値は決まった既定（`internal/ledger` の `DefaultSettings`。Chief of Staff の `playbooks/brief.md` の表の既定）: `must_fix=major`・`merge=person`・`estimate=medium`。`review` が `on` のときだけ `reviewer`（実装と別ブランド。`codex*` のプロファイルなら `claude-review`、ほかは `codex-review`）と `review_rounds=2` も書く。`off` のときに書くと足した時点の profile で固定され、あとで Chief of Staff が profile を替えると同じブランドのレビュアーが起動されるので書かない（書かなければ読むときの profile から選ばれ、`andon issue start` も求めない）。`review` はトリアージの決定の `review`（束ならどれか1つが `on` で `on`）、ほかは `off`。ルーチンの定義に欄は足さない。
- `andon triage apply` は、`fix`・`bundle` の決定を、足す前の印（`adding`）と一緒に記録（`library/triage/<日付>-<id>.json`）に書いてから `kanban add` し、足した課題を記録の `created_issue` に書いてから、その課題へ予約キーを全部 `kanban set` する。add が返ったあと記録の前で止まっても、印と題と、足したのが Chief of Staff の端末か（`log.jsonl` の add の行）で課題が分かる。記録のあと set の前で止まっても、`andon issue start` が記録からトリアージの足した課題と分かり、無いキーを既定（`review` は決定の値）で書いて起動する（下のルーチンと同じ）。打ち直しは今までどおり記録済みで断るので、課題を重ねて足さない。依頼書の `## Settings` に同じ値の写しを書く。`andon retro apply` は、担当の課題（`who: person` でない）に同じことをする（`review` は `off`）。打ち直しで前の回が足した課題を見つけたら、無いキーと、既定と同じ値なのに照合が外れたキー（`kanban set` が `issue.yaml` を書いたあと `log.jsonl` に足す前に止まった・Chief of Staff が起き直した）だけを書く。既定と違う値は Chief of Staff が選んだものなので触らない（`internal/ledger` の `Unsettled`）。`profile` は今までどおり書かない。どちらも Chief of Staff の端末で打つので、`andon issue start` と gate の履歴の照合が通る。
- ルーチンが足した課題（`log.jsonl` に `by: routine:<名前>`・`fired: <id>` の行があり、課題の `routine` がその名前）は、dispatcher の `kanban tick` が足すので、足すときに Chief of Staff の書いた値を持てない。そこで `andon issue start` が、Chief of Staff の端末（`HC_TERMINAL_ID` が `config.yaml` の `chief_of_staff`）で打たれたときだけ、要るキーのうち無いものを既定（`review` は Chief of Staff が `on` を書いていなければ `off`）で埋めて起動する。要るキーは埋めたあとの課題で数える。書くのは起動の前で、`--dry-run` は書かずに確かめの行で埋めるキーを出す。既定と同じ値なのに照合が外れたキーも、同じ値で書き直す（前の start の `kanban set` が途中で止まった・Chief of Staff が起き直した）。既定と違う値は変えず、照合が外れていれば今までどおり断る。`routine` の欄だけがあって行が無い課題と、ほかの端末で打ったときは埋めない。
- 変えないもの: Chief of Staff が切る課題は今までどおり断り、値を選ぶ場所を残す。gate・dispatcher の履歴の照合（`terminal:<chief_of_staff>` だけを信じる）は広げない。
