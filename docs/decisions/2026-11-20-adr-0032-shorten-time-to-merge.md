# ADR-0032: 書き終えてから main に入るまでの時間を、順番と重複の直しで縮める

- 日付: 2026-11-20
- 出典: ADR-0032（[adr/0032-shorten-time-to-merge.md](../adr/0032-shorten-time-to-merge.md)。Chief Engineer の課題。オーナーが対話の中で決めた。元は人の発言 2026-11-20「マージと開発のサイクルをもう少し早めたい」）

目的を CI の job の秒数でなく、担当が書き終えてから main に入るまでの時間に置く。担当は PR を出したらすぐレビューを頼み、CI とレビューを並べる（レビュアーは 1 人ずつ。動いている間の頼み直しは command が断る）。`tests/schema.sh` がほかの検査を回し直す重複をやめ、手元は軽い検査と変えた所に対応する重い検査だけにする。CI の検査の顔ぶれと required checks は変えない。テストより手前の手段（lint・動的な検証・型・レイヤ・性能の計測・形式仕様・モデル検査）で防げるものはそちらへ寄せ、残る場面の確かめは dispatcher の検査から Go のテストへ移す。流れの順や状態の移り方を変える変更は、実装の前にモデルに書いて確かめる（最初はレビューを CI と並べる変更）。release の job の上限は 30 分のまま。2026-11-27 に実測を見る
