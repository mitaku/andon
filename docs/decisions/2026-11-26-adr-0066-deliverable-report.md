# ADR-0066: 成果が報告で PR が無くてもよい課題に、予約キー deliverable の値 report を足す

- 日付: 2026-11-26
- 出典: ADR-0066（[adr/0066-deliverable-report.md](../adr/0066-deliverable-report.md)。Chief Engineer の課題。元はオーナーの 2026-11-25 の答えで、PR を出さずに終える課題を完了と読むために、印を予約キーで持たせると決めた。オーナーは 2026-11-26 に、この文書の中身を「決めた」と答えた）

PR を出さずに終えてよい課題（当てたあとの検証・点検・マージ後のレビュー）は、記録の上ではやめた課題と同じ形になり、後ろの課題に「待つ相手がやめになった」と誤って知らされていた。予約キー `deliverable` に 3 つ目の値 `report` を足す。意味は「成果は報告で、PR は無くてもよい。出した PR は PR の課題と同じ道を通る」である。書くのは Chief of Staff で、課題を切るときに書く。dispatcher は、`report` の課題を待つ相手がやめになったかの見分けから外す。`andon issue merge` は、`review` に入った `report` の課題に `pr` が無ければ、報告の commit を見ずに gate を回さない。値 `report` は、キーを最後に変えた行の書き手が、その行の時点の Chief of Staff の端末だったときだけ信じる。Chief of Staff が起き直しても打ち直しは要らず、担当が書いた `report` は `pr` として読む。印の無い課題と知らない値は、今までどおり `pr` として読む。値ごと・読み手ごとの振る舞いの表の正は、contract.md §2 に小さい節で置く。

捨てた案:

- **印だけにそろえ、報告の commit での見分けをやめる**: PR の課題が直さずに返す場合に、返し方を新しく作る必要がある。
- **検証の課題から PR を無くす**: 検証 49 件のうち 18 件が検証の地図を直す PR を出していて、課題が 1 つずつ増える。
- **別の予約キーで持つ**: `deliverable: pr` と食い違う組み合わせが書ける。
- **kanban の履歴で完了とやめを分ける**: 本物の記録に両向きの反例がある。
- **値だけで読む（`candidates` と同じ）**: 担当が自分で `report` を書いて、やめた課題から句を消せる。
