# トリアージの collect は、項目が 50 を超えるときだけ memory と signal を先頭に寄せる

- 日付: 2026-11-21
- 出典: オーナーの言葉（2026-11-21）「直す」。前のトリアージで、たまった項目が 809 件になり、memory と signal の項目が列の後ろに残った

- `andon triage collect` の `items` は古い順に並ぶ。項目が 50（`--limit` の既定）を超えるときだけ、`memory` と `signal` の項目を先頭に寄せる。その中と残りの並びは古い順のまま。50 以下のときの並びと出力の形は変えない。
- 理由: 項目が上限を超えると、トリアージの担当は `--limit` を増やして全件を取り直し、先頭から決まった件数（既定 50）だけ仕分ける。古い順のままだと、新しく入る memory と signal がいつまでも後ろに残る。memory は仕分けるまで全部の役のコンテキストに載り続け、signal は外で起きている不具合なので、先に仕分けたい。
- 寄せる線は、渡した `--limit` ではなく既定の 50 で決める。担当が取り直すときは `--limit` を大きくするので、渡した値で決めると寄せる日が来ない。
- 変えないもの: 上限の数（50）と `--limit` の意味、`decisions.json` と `apply` の形、key の作り方。`apply` の中で集め直す項目の並びは照らすのに使わない。
