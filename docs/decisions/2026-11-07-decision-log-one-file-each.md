# 決定の記録は 1 件 1 ファイルで `docs/decisions/` に足し、decisions.md の表は凍結する

- 日付: 2026-11-07
- 出典: 人（2026-11-07「decision.md がコンフリクトを誘発している」）、Y-199
- 覆された（一部。語の置き換えだけ）: [2026-11-10-word-replacement-reaches-frozen-records.md](2026-11-10-word-replacement-reaches-frozen-records.md)

決定の記録の置き場を改める。今までは [decisions.md](../decisions.md) の表の末尾に 1 行ずつ足していたので、並べて走る PR がどれも同じ所を触り、1 本マージされるたびに次の PR が rebase を要した（直近の main の 30 commit のうち 12 がこのファイルを触っていた）。

- 新しい決定は `docs/decisions/YYYY-MM-DD-<英字の短い題>.md` に 1 件 1 ファイル。ADR 1 本にも 1 ファイル（`YYYY-MM-DD-adr-NNNN-<題>.md`）。書き方は decisions.md の冒頭。
- decisions.md の §1〜§22 は凍結する。行も § の番号も動かさないので、今までの「decisions.md §N」の参照は生きる。足してよいのは古い行への「→ 覆された」の注だけ。
- 一覧のファイルは作らない。名前の順（日付が先頭）がそのまま一覧になる。
- 上書きしない・覆したら新しく足す・ADR 1 本に 1 件、の規則は変えない。覆すときは新しいファイルの `- 覆す:` に前の決定を書き、前のファイルには `- 覆された:` の 1 行だけを足す。

捨てた案:

- **既存の行を全部 1 件 1 ファイルに移し、一覧を生成する**: 一覧を commit すれば、それが次のぶつかる所になる（生成し直しても git の衝突は起きる）。commit しなければ GitHub で読む人に一覧が無い。移すと、repo の中の 80 か所ほどの decisions.md への参照（うち 40 ほどは § の番号で指す）が切れるか、指し直しが要る。
- **`.gitattributes` の `merge=union`**: 手元の merge・rebase には効くが、GitHub の PR のマージの判定とボタンには効かない。行の順も保証されない。
- **節を PR ごとに分ける**（今のやり方）: 節を足す所がファイルの末尾なので、ぶつかる所は変わらない。
