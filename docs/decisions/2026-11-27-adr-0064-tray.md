# ADR-0064: tray（セルが出した報告を集めて読む場所）を andon に足す

- 日付: 2026-11-27
- 出典: ADR-0064（[adr/0064-tray.md](../adr/0064-tray.md)。Chief Engineer の課題。元はオーナーが 2026-11-24 に書いた brief で、報告を読む場所が端末の返事と、セルを動かしている PC でしか開けない `files/` の URL に限られ、スマホで読めず、既読も残らないことを直す）

セルが出した報告を集めて読む場所 tray を、andon の repo の `tray/` に置くサブシステムとして足す。tray は読むだけの場所で、判断に答える口も通知も持たない。届くのは、`andon publish`、`andon digest send`、`andon issue report` が出した物である。役は、3行を超える報告と表を含む報告をファイルにして `andon publish` で出し、返事には URL と要る判断だけを書く。セルの中で動くローカルの tray が、`files/` の配る口（files サーバと portless の名前 `files`）を置き換える。オーナーが `project.json` に `tray` を書いたプロジェクトだけが、Cloudflare の tray にも送る。同じ Workers のコードを、セルの中では workerd で動かす。Cloudflare では、一覧の面、報告の面、アップロードの口を別のホスト名と別の Worker に分ける。一覧の面は Access の内側に置いて Worker も JWT を確かめ、報告は短い期限の署名付き URL で別オリジンから `sandbox` 付きで出し、アップロードはセルごとの API キーで受ける。既読は、開いたバージョンの番号をサーバに書いて持ち、上げ直すと未読に戻る。30日を過ぎた報告は古い報告のページへ移し、既定では消さない。スタックは Solid 2.0、UI SDK、StyleX、Workers、D1、R2 で、バージョンを固定する。ADR-0028 の「受け口、保存先、常駐を足さない」前提を tray の範囲で改め、ADR-0044 のやらないこと（専用のサイトを外に立てない、長い返事を HTML にする決まり、Slack のほかの送り先）を覆す。tray に届いた報告は `files/` に写さない。Cloudflare へのデプロイはオーナーがセルの外から打ち、セルに Cloudflare の資格情報を置かない。

捨てた案:

- **ローカルは files サーバのままにして、Cloudflare の tray だけを作る**: 既定のローカルの tray が無く、選んでいないプロジェクトは何も変わらない。セルの中で完了の条件を確かめる場が無い。
- **ローカルの tray を Go で書き、Cloudflare は Workers で書く**: 軽いが、一覧、既読、署名、ヘッダを2つの言語で書くことになり、セルの中の検査が Cloudflare で動くコードを確かめなくなる。
- **1つの Worker をホスト名で振り分ける**: 振り分けの誤り1つで、Access の外から一覧が読める。
- **担当の skill に、報告を HTML にして出す手順を書く**: 同じ中身を2度書かせ、書き忘れを検査できない。`andon issue report` が送る。
- **セルに Cloudflare のトークンを置いて役がデプロイする**: 役がオーナーのアカウントに好きな Worker を出せる。
- **tray に送れなければ `andon publish` を失敗にする**: tray が落ちている間、どの報告も出せなくなる。
