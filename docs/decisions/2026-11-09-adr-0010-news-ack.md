# 通知を「記録だけ」と「届ける」に分け、`<no-reply>` の照合を `andon news ack` に替える（ADR-0010）

- 日付: 2026-11-09
- 出典: ADR-0010・人（2026-11-09「no-reply と返すとかってどうなんだろうね。もっと上手いことできないのかな」）・課題 A-0009

中身・理由・捨てた案は [ADR-0010](../adr/0010-news-ack.md) が正。要点:

- dispatcher は通知の kind ごとに「届ける」か「記録だけ」かを固定する。記録だけ（`review-requested`・担当の課題の `review`・`gate` の `fix` と `needs_human`・`merged`・レビュアーの課題の `report`・`merge: auto` の `gate: approve`〈10 分たっても `merged` が無ければ届ける〉）は `<news>` に載せず、`~/.local/state/andon/dispatcher/<slug>.recorded.jsonl` に通知の JSON を1行ずつ足す（書き手は dispatcher だけ）。`ready` は今は届ける。
- Chief of Staff は人に言うことが無ければ `andon news ack` を打ち（ラベル `news.ack=<turn>`）、文を書かずにターンを終える。
- **`news.replied=<turn>` を書くきっかけが変わる**: 答えが `<no-reply>` だけか（文字列の照合）から、渡したターンに `news.ack` があるかへ。ラベルの意味（そのターンは人が見る返事ではない）・名前・値は変えない（decisions.md §7 の F8。持ち主は herdr-flightdeck 側）。decisions.md の 2026-11-05「フックで渡した `<news>` の `news.replied` は `last_assistant_message` で決める」の行は、ack を入れた版の次の版で覆す（その版の決定で「→ 覆された」を付ける）。
- 移行: ack を入れた版では `<no-reply>` も受け、その次の版で照合を外す。
