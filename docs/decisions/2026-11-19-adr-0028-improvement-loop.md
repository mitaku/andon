# ADR-0028: 実行の記録から skill とプロンプトを直し続けるループ（記録・振り返り・改善の PR）

- 日付: 2026-11-19
- 出典: ADR-0028（[adr/0028-improvement-loop.md](../adr/0028-improvement-loop.md)。オーナーが Chief Engineer との対話の中で決めた。元はオーナーが 2026-11-19 に貼った文書「プロンプト／スキル継続改善ループ」と、同じ日の発言「後回しグセがついているように思う」「ライフサイクルが長過ぎるかもね、もっと高頻度でやってもいいかも」）
- 覆された（一部。直す課題の上限・毎日・パッケージに触れる改善の PR の自動マージ・振り返り自身の扱い）: [2026-11-20-adr-0039-retro-scale-with-flow.md](2026-11-20-adr-0039-retro-scale-with-flow.md)

アウターループの振り返り（retro）を、設計だけの状態から、回る仕事にする。記録は2つ足す: エージェントを起動するたびに書く起動の記録（パッケージ・セルの repo・案件の repo の commit、実際の起動行、ハーネスの版、外の skill の版、auto memory の目録の写し、食い違いの印）と、dispatcher が片付けのときに1回だけ書く結果の記録（結果・ゲートの判定・実働の時間・セッションごとのコスト）。マージ後のこと（revert・main の CI の失敗）は、読むときに GitHub から数える。振り返りはルーチンが毎朝1回足す調べる課題で、トリアージと同じ3段（`andon retro collect` が集める・担当がパターンを書く・Chief of Staff が `andon retro apply` で直す課題に切る）。読むのは直近 7 日に片付いた課題と、セッションログから抜いたオーナーが打った文。根拠は別々の2件以上で、うち1件以上は前回の振り返りより後のもの。直す課題に切るのは1回2件まで。これらと、skill か文面を直すときの「上の段で止められない理由」、振り返り自身を直す先にしないことは、command が断って守る。直す先は効き目の確かな順に5段（設計・型、テスト・lint、決まった手順の確かめ、skill・指針、文面）で、削ることも候補にする。直しが効いたかは、次の振り返りが再発を数える。改善の PR はふつうの直す課題の PR として出し（ラベル `retro`）、マージはラインの決まりに任せる（Andon のパッケージに触れるものはオーナー）。Andon を開発するセルでは、トリアージも毎日回す。価値の仮説を置く（見る日 2026-12-10）。リプレイの評価・カナリア・自動ロールバック・パッケージに触れる改善の自動マージは範囲の外で、メモだけ残した。中身・理由・捨てた案は ADR が正。
