# ADR-0016: 仕事の流れと状態を定義し、その上で dispatcher を細くする

- 日付: 2026-11-10（提案。オーナーの確かめは朝。確かめが済んで PR がマージされた日が決定の日）
- 出典: ADR-0016（[adr/0016-process-definitions.md](../adr/0016-process-definitions.md)。Chief Engineer の課題 A-0085。指示文 P11〈オーナー。2026-11-10〉。対話はオーナーが寝ている間に Chief of Staff と進め、オーナーの決断に当たる項目は「仮」）

Chief of Staff の定常の仕事（ワークストリーム 8 本。中身は見守りと仕分けから）と、もの（課題・担当の端末・通知の配達・レビュアーの起動・ゲートとマージ・人のマージの見張り・片付けのあとの仕事・外のお知らせ）の一生を、YAML の定義（`process/`。JSON Schema で検査）として 1 か所に書く。人が読む Markdown と Mermaid の図は `andon process render` が YAML から作り、定義と実装の食い違いはテストで見る（dispatcher は定義を読まない。読ませるのは後の題）。定義の上で、dispatcher の中の「機械がやる仕事」（人のマージを拾って片付ける・ゲートのあとのマージと片付け・手直しを集める・影響の打ち直し・レビュアーを起こす）をこの順で独立したコマンドに出し、どれも 2 回打っても同じ結果になり自分の記録ファイルを持つ（通知は stdout で返し、待ちに積むのは dispatcher だけ）。dispatcher に残すのは「定義のきっかけ表のうち時が来たものを打つ」と「通知を配る」だけで、記録ファイルに残すのは配達・拾う位置・担当の端末の判定・留守の始まりだけ。Chief of Staff が居ない間も拾う・起こす・tick は回し、配る段とゲートのあとのマージだけ止める。ルーチンは課題を足すもののまま（間隔の仕事はきっかけ表に。signal の間隔は `project.json` のまま）。見守りは ADR-0014 を指す（1・2・4 倍。担当には送らない）。担当の計画は `report.json` の `plan[]`。詰まりの兆しは commit 無しと変更の量の 2 つを段の通知に載せる。役の呼び方は用語集の語のまま。大きさの目安（きっかけ表 8 行・記録 12 項目・2,700 行）は repo のテストと CHANGELOG で数える。課題の状態ごとの時間は measure に足す。R1〈A-0066〉・R2〈A-0067〉は吸収せず先に流す。決めたこと 17 件・切る案 P1〜P14 と S3 の切り直しは ADR が正。
