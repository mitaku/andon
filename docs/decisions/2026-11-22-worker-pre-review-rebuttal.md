# 担当は1回目のレビューを頼む前に、読むだけのサブエージェントに自分の差分を壊させ、落ちる検査を書けた疑いだけを直す

- 日付: 2026-11-22
- 出典: 3日間（2026-11-19〜21）の実行の記録の集計。1回目のレビューで major が見つかって2回目に回った PR が17件あった。見落としの多くは、変えた関数を包んだ別の呼び出し元、状態を書くコマンドの並行の実行、入力のファイルが無い・空・読めないとき、2つの入力の片方だけに値が欠けるとき、木やグラフをたどるときの循環だった。Chief Engineer が ADR-0043 の検討で読むだけのサブエージェントに設計へ反論させ、13件の指摘を事前に拾えた。

worker skill §4 に、`Review: on` の課題で1回目の `andon issue review-request` の前（PR を出す前）に通す反論の段を置く。

- 反論役に渡すのは、`origin/main` との差分と依頼書のパスだけ。報告・計画・日報・担当の見立ては渡さない。同じ思い込みを写さないため。
- 反論役は、その turn のうちに返る読むだけのサブエージェント。ファイルを書かず、直さず、commit しない。major 以上の疑いだけを、起きる条件と一緒に返す。
- 見させる観点は5つ。包む呼び出し元・並行の実行・無い・空・読めない入力・片方だけ欠ける入力・たどる循環。
- 担当は疑いを1件ずつ、今の head で落ちる検査に書けるか試す。落ちる検査を書けた疑いだけを直し、直しを戻すと落ちることを確かめて検査ごと commit する。書けない疑いは捨て、直さない。
- サブエージェントを起動できないプロファイル（Codex など）では、担当が依頼書と差分だけを読み直して同じ段を自分で通す。止まらない。
- 報告の `## Report` に `反論:` の行を1行書く（走らせ方、疑いの数、直した数と検査の名前、捨てた数）。疑いが0件でも書く。
- 2回目からの頼み直しと rebase のあとの頼み直しでは通さない。再レビューは直した差分だけを見るため。
- レビュアーの役と依頼書は変えない。
- `tests/package/29-pre-review-rebuttal.sh` が、段と観点と確かめ方と、工程表・§3・§4 の 1・§7 の書式から指す行が消えたら落とす。

引き受けたリスク:

- 自分で通す担当は、サブエージェントより思い込みを写しやすい。差分と依頼書だけを読み直す手順で薄めるが、別の目と同じにはならない。
- 落ちる検査を書けない疑いを捨てるので、検査に書きにくい種類の誤り（文書の語の食い違いなど）はレビュアーに残る。

捨てた案:

- **反論役が全部の疑いに落ちる検査を書く**: 反論役は読むだけで、書けば担当の worktree の外か中を触ることになる。検査は担当が書き、書けない疑いは捨てる形で取り入れた。
- **反論の段を別の skill にして、Stop フックで通したかを見る**: 段を通したかを機械で見る口が要り、報告の1行で足りる今は重い。
- **サブエージェントを起動できないプロファイルでは段を飛ばす**: 3つの観点と同じく、自分で当てるだけでも拾える見落としがある。
