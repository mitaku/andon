# ADR-0067: オーナーのマージを待つ PR の branch の上で、後ろの課題を起動する

- 日付: 2026-11-27
- 出典: ADR-0067（[adr/0067-stacked-start.md](../adr/0067-stacked-start.md)。Chief Engineer の課題。元はオーナーの 2026-11-25 の言葉「オーナー確認待ちが溜まったから工場が止まるというのは変です。」と、ADR-0065 決めたこと 2）
- 覆す: [ADR-0042](../adr/0042-owner-waits-do-not-stop-the-line.md) 決めたこと 11 の前半（マージ待ちの後ろに並べた課題は先に起動しない。一部。待ちが止めている課題を見せて多い順に出すことは生きている）。decisions.md §の表の 2026-11-03 の行（【仮】積み重ねた PR は採らない。一部。小さい PR を順に流すことは生きている）。decisions.md §の表の 2026-11-05 の行（conflict と、base が既定ブランチでない PR は、いつも `needs_human`。一部。積んだ PR だけは、積んでいる間、理由にしない。ほかの PR では生きている）。[2026-11-19-settle-doing-merged-pr.md](2026-11-19-settle-doing-merged-pr.md)（マージされた PR は settle が片付ける。一部。既定の branch でない base にマージされた PR だけは片付けない）

`after` で前の課題を待つ担当の課題は、前の課題がオーナーのマージを待っている間、起動されずに待っていた。3 日半で 13 件、合計 1,140 分である。待つ相手が 1 つだけ残り、その PR を gate が今の head で通している課題は、前の課題の PR の branch の上で起動できるようにする。`andon issue start` が branch を前の課題の PR の head から切り、前の課題と分かれ目の commit を課題の予約キーに控える。kanban は、積んだ相手を待つ相手に数えない。積んだ PR は draft で出し、向き先を前の課題の branch にする。GitHub の Stacked PR の機能には、今は登録せず、実測してから決め直す。積んでいる間、gate は approve もオーナー待ちも決めず、今ならそうなる判定を、新しい判定 `behind`（前の PR 待ち）に置き換える。差分は分かれ目から数える。前の PR 待ちの課題は並行の枠にもオーナー待ちにも数えず、`slots.behind` に出す。積んだ課題は、前の PR が動いても追わない。前の課題が main に入ったら、gate が担当に載せ替えを頼み、担当は `andon issue restack` の 1 つで、自分の commit だけを既定の branch の先へ移し、PR を main へ向くふつうの PR にする。前の課題がマージされずに終わったら、積んだ課題をどうするかを、Chief of Staff がオーナーに 1 問聞く。既定の branch でない base にマージされた PR は、片付けずに Chief of Staff へ知らせる。積む深さに上限は置かない。取り直しを減らす仕組みは、次のテーマで設計する。

捨てた案:

- **GitHub の Stacked PR の機能に登録して、載せ替えを GitHub に任せる**: GitHub が担当の知らない所で head を書き直し、報告と gate が回り直る。main が進むとマージの前に stack の rebase が要るおそれがある。設計が頼る 6 つの点が文書に無い。実測してから決め直す。
- **PR を出さず、前の課題が main に入るまで担当が手元で待つ**: レビューと CI を先に済ませられず、待つ間も並行の枠を 1 つ塞ぐ。
- **積んだ列の PR をマージ commit で入れて、載せ替えを無くす**: オーナーが PR ごとにマージの仕方を選び分けることになり、選び損ねたときの載せ替えの道も結局要る。
- **止め（hold）を使い回して、積んだ課題を機械が止める**: 止めている課題に gate は回らず、CI の失敗が前のマージのあとまで見つからない。
- **積んだ PR でも、オーナーへ回す理由があれば回す**: 押せないマージの依頼がオーナーに届く。
- **前の PR が直されるたびに、積んだ課題も追う**: 載せ替えが、前の課題の直しの回数だけ増える。
- **積む深さを 1 段までにする**: 3 つ以上並んだ列が、2 つ目のマージ待ちでまた止まる。
- **dispatcher が自分で載せ替える**: 担当の branch に機械が push することになり、役の持ち場が変わる。取り直しをまとめる仕組みと一緒に、次のテーマで決める。
