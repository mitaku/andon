# ADR-0030: トリアージが誤って閉じた項目を拾う網

- 日付: 2026-11-19
- 出典: ADR-0030（[adr/0030-triage-close-safety-net.md](../adr/0030-triage-close-safety-net.md)。オーナーが Chief Engineer との対話の中で決めた。元は同じ日の発言「必要なものが 5 件以外にあった場合は？」「んー、それは少し危ないんじゃないかな」）

トリアージの `close` は片道で、閉じた項目は二度と候補に出ない。誤りを拾う網を2段で組む。1段目は、判断で閉じられる範囲を機械で狭める: `close` の判定は閉じ方の種類の欄を必ず持ち、`andon triage apply` が項目の種類との組み合わせを確かめる。根拠の閉じ（「済み」「対象が無い」と、行き先がある閉じ）は今のまま通す。判断の閉じ（「起きない」「その場限り」「当てはまらない」「読んだ」）は、決めた種類の項目にだけ許し、やり残しの行・担当の無い課題・外の信号などは判断では閉じられない。`collect` は「計画との差:」の行と、報告の無い人の課題を拾わない。2段目は、残った判断の閉じを Chief of Staff が1件ずつ読む: `apply --dry-run` が別の表で出し、Chief of Staff が閉じてよいか覆すかを command で書き、判定が揃わなければ `apply` は断る。確かめる先は command が決める: `collect` が最新の main を取って commit を出し、`apply` が担当の見た commit を照らす。台帳の課題そのもの（人の判断待ちの課題・担当の無い課題）を閉じる判定は、根拠があっても Chief of Staff が読む。「その場限り」の線は判定表に書かず、Chief of Staff の見立てに任せる。2026-11-19 の朝に閉じたもののうち、失われうると出た 2 件は戻す。起動する上限 3・周期・根拠の閉じの機械での照合・戻すための新しい command は範囲の外。価値の仮説を置く（見る日 2026-12-10）。中身・理由・捨てた案は ADR が正。
