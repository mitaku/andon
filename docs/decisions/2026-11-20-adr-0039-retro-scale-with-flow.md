# ADR-0039: 振り返りの直す課題の上限を外し、改善のペースを流量に合わせる

- 日付: 2026-11-20
- 出典: ADR-0039（[adr/0039-retro-scale-with-flow.md](../adr/0039-retro-scale-with-flow.md)。Chief Engineer の課題。オーナーが対話の中で決めた。元はオーナーの発言 2026-11-20「振り返り上限によって改善が進まないのは本末転倒に思い始めてきた。」）
- 覆す: [2026-11-19-adr-0028-improvement-loop.md](2026-11-19-adr-0028-improvement-loop.md) のうち、1 回に切る直す課題は 2 件まで・毎日回す・Andon のパッケージに触れる改善の PR は自動でマージしない・振り返り自身は直す先にしない、の 4 点
- 覆された（一部。`AGENTS.md`・テンプレート・モデルの規則はオーナーのマージのまま、としたこと）: [2026-11-21-adr-0041-delegation-cap-out-of-command.md](2026-11-21-adr-0041-delegation-cap-out-of-command.md)

1 回の振り返りが切る直す課題の数に、上限を置かない。振り返りの入力は、前の振り返りが集めたあとの束を全文で、それより前の束を要約で出す。振り返りは、片付いた担当の課題が 25 件たまるごとと毎朝に回す。Andon を開発するセルでは、skill に触れる PR をレベル B に下げ、独立レビューと checks が通れば自動でマージする。振り返りは自分自身も直す先にできる。あとの 2 つは、Andon のバージョンが v0.0.x の間の決まりである。中身・理由・捨てた案は ADR が正。
