# 待ち役のフックの timeout は 7200 秒で、その 9 割で張り直す。待ち役は控えの横の `<slug>.json.wait` の印で端末に 1 つにする

- 日付: 2026-11-11
- 出典: ADR-0019 決めたこと 8・9（`timeout` の値と待ち役の持ち方は実装の課題が決める）。ADR-0019 の事実（`timeout: 7200` が置けて、600 秒を超えて 11 分待った待ち役がセッションを起こした実測）。課題 A-0133

- `package/settings.json` の Stop の待ち役（`/opt/andon/hooks/stop-wait`。`asyncRewake: true`）の `timeout` は 7200 秒。待ち役には同じ値を `--timeout` で渡し（`tests/package.sh` が突き合わせる）、その 9 割（6480 秒）まで打つ機会が無ければ張り直しの合図で終わる。理由: 置けることと 600 秒を超えて効くことを実測で確かめた値の中でいちばん長い。もっと長い値（ADR の例は 12 時間）は、置けて生きるかを実測してから上げる（ADR-0019 の受け入れ条件 3）。余白を 9 割にしたのは、Claude Code が `timeout` で切る前に確実に自分で終わるため。払うのは静かな間 約 1.8 時間に 1 回の短いターン。
- 働いている間（`working`・`blocked`・`error`）に張り直しの時刻が来たら、合図を打たずに 0 で終わる。そのターンの終わりの Stop で次の待ち役が起きるので、ターンの途中に合図を入れない。
- 待ち役は起きると控えの横の `<slug>.json.wait`（端末・pid・印）を書き替え、前の待ち役はそこが自分の印でなくなったら 0 で終わる（シグナルで止めない。1 秒ごとに読み直す）。dispatcher はこの届けと pid で「待ち役がいるか」を見て、いなければログに 1 行だけ書く（同じ待ちには 1 回。dispatcher のプロセスの中で覚える）。
- 控えから `coord`・`news_turn`（経路③の `hc send` で送った turn）を外した。古い控えに残っていても読み捨てる。
