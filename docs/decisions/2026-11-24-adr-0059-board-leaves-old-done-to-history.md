# ADR-0059: ボードは片付いて 24 時間を超えた課題を毎回は読まず、表示 History に分ける

- 日付: 2026-11-24
- 出典: ADR-0059（[adr/0059-board-leaves-old-done-to-history.md](../adr/0059-board-leaves-old-done-to-history.md)。Chief Engineer の課題。元はオーナーの 2026-11-23 の 1 行で、ボードの mod が片付いた古い課題を読み込まないか、別の表示にしたほうがよいということ）

mod `kanban-board` は、片付いた課題の全部を 10 秒ごとに読み、Board の Done の列に番号の順で全部並べていた。課題 735 件のうち 638 件が片付いていて、1 回の読みに 2.0 秒かかった。片付いて 24 時間を超えた課題は Board と List から外し、Done の列は新しい順に並べる。古い課題は、4 つ目の表示 History で新しい順に見て、全部から探せる。Flow の出し方は変えない。毎回の読みは、読むだけの command `andon issue board` をセルで呼んで受ける。出すのは、片付いていない課題、24 時間以内に片付いた課題、その 2 組の親をたどった先と `after` の相手、片付いていない課題の親をたどった先の課題を親に持つ課題だけである。History は `andon issue history` で読む。2 つの command は `issue.yaml` を自分で読み、symlink、大きすぎるファイル、alias のあるファイルの中身を出さない。command が使えないとき、mod は今の読み方に戻り、同じ見せ方を当てる。kanban のファイルと形式は変えない。

捨てた案:

- **決まったシェルの文を軽く書き直し、片付いた課題を文の中で外す**: `issue.yaml` を読む実装が 3 つ目になり、読む前の symlink と大きさの守りを保ちにくい。
- **`kanban list` にフラグを足す**: 古い `kanban` は知らないフラグを黙って読み飛ばし、片付いた課題が欠けたことに mod が気づけない。kanban の CLI に葉を足さない決まりにも当たる。
- **見せ方だけを変える**: 読みは課題の数に比例して重くなり、約 12,600 件で新しい課題から読めなくなる。
- **片付いた課題を kanban の中の別のフォルダへ移す**: 形式が変わり、kanban を読む全部の command に効く。
- **新しい順に決まった件数だけを Done の列に出す**: 1 日に 150 件片付く速さでは、50 件は 8 時間分にしかならない。
