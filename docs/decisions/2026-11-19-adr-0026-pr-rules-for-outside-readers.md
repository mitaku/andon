# ADR-0026: PR と repo に残る文は、セルの外の読み手に通じるように書く

- 日付: 2026-11-19
- 出典: ADR-0026（[adr/0026-pr-rules-for-outside-readers.md](../adr/0026-pr-rules-for-outside-readers.md)。オーナーが Chief Engineer との対話の中で決めた。元はオーナーの発言 2026-11-19「A-000Xなどは手元で作成されているIssueIDのため、PullRequest上のタイトルに出てきていても他の人が困る」）

規則は 1 本で、「その repo と PR だけで解けるものだけ書く」。Andon の repo では Andon の用語は書いてよく、セルの具体物（実在の課題番号・セルのパス・wiki や台帳のページ・端末の名前）だけ書かない。案件の repo では Andon の用語も書かない。課題番号は PR の本文の末尾の控え 1 行（`Memo: 内部の課題番号 <id>`）にだけ置き、PR の題・commit の題と本文・ADR の題・コードのコメントには書かない。セルの中の物を根拠にするときは中身を写す。PR の本文は 6 つの見出し（変更理由・やったこと・変更範囲・トレードオフ・影響範囲・検証結果と確かめ方）で、1・2・6 番目が必須。長い物だけ `<details>` に畳み、状態の移り方を変える変更には変更前後の状態の図を載せる。守らせるのは担当の手引きだけで、機械の検査は足さない。ゲートが PR に書くコメントと外の Issue への書き戻しは、外の人が読める文に直す。過去の PR・履歴・文書と、まだマージしていない PR は直さない。branch の名前は変えず、マージしたら remote の branch を自動で消す設定を入れる。価値の仮説は置かない。中身・理由・捨てた案は ADR が正。
