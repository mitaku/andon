# ADR-0024: 担当が課題ごとに日報（過程・感想・改善の思いつき）を書く

- 日付: 2026-11-12
- 出典: ADR-0024（[adr/0024-worker-journal.md](../adr/0024-worker-journal.md)。Chief Engineer の課題 A-0186。オーナーが対話の中で決めた。元は人の発言 2026-11-12「Kanban の Issue にそれぞれ作業者の日報とか書いてもらうと改善にいいかも」）

担当は、台帳の自分の課題のフォルダの `issues/<id>/library/journal.md` に日報を書く。詰まった・迷った・回り道した・うまくいった、のその場で 1〜数行を追記し、報告を書く前に「感じたこと」「改善できそうなこと」を足す。日報は検収・ゲート・見守りの判定に使わず、機械は読まない。今の報告の書式（Remember・計画との差・Next）は変えない。書くのは担当だけ。誰がいつ読んで環境の直しにつなげるかは、たまった日報を見てから別の題で決める（オーナーが「まず書かせる」を選んだ）。それまでは台帳に置いておき、見る日（2026-11-26）に観察の課題がまとめて読む。オーナー向けの Daily の報告書も別の題。中身・理由・捨てた案は ADR が正。
