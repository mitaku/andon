# ADR-0034: 検査の仕分けから、テストより手前に足す道具と直す設計を決める

- 日付: 2026-11-20
- 出典: ADR-0034（[adr/0034-prevention-before-tests.md](../adr/0034-prevention-before-tests.md)。Chief Engineer の課題。オーナーが対話の中で決めた。元はオーナーの発言 2026-11-20「リントルール、動的検証、静的型設計、レイヤ設計、性能測定、形式仕様、モデル検査などで防止できるものはそっちに寄せるなどしましょう」）

ADR-0032 の開いている問い 1 と 4 に答える。足す道具は golangci-lint で、2 段で入れる（1 段目は errcheck 以外、2 段目で errcheck をテストと出力への書き込みを除いて入れる）。設定ファイルはオーナーがマージする変更に足さない。repo に固有の規則は Go のテストと字面の検査で書き、今入れるのはフックの 1 行目と、全部の workflow を actionlint・ghalint・pinact に通すことの 2 つ。schema の照合は既製の Go の検査器 1 つに一本化し、`andon` は約束の JSON を書く前に照らす（Python と kanban のテストの自作の照合はやめる）。`log.jsonl` の行と `kanban ready --json` の schema を足す。`andon issue report` は課題の repo と違う repo の PR を断る。課題の一生のモデルに、gate が決めたあとの変化（head が動く・PR が閉じて開き直される・merge の設定と委譲が変わる）と、「自動でマージするのは、ゲートが approve と判定した head で、その時点で任されているものだけ」の規則を足す。型は 3 つ（失敗を数えて諦める控え・予約キーの照合を通った値・gate の落ち方）を、その節を Go へ移す課題の中で直す。dispatcher の節を Go へ移す手順は「Go に欠けた確かめを足す → わざと壊して落ちることを確かめる → シェルから消す」に改め、消すだけの課題は作らない。検査の秒数の上限・レイヤの依存の規則・動かすときの gh の回数の上限は置かない。gate とオーナーのマージの状態の定義をモデルと照らすかは、モデルを広げた結果を見てから決める。価値の仮説は置かない（利用者に見えないテーマ）
