# Cloudflare の tray は、上げ直しで古くなった中身を、R2 に置いてから 1 日を過ぎたものだけ、次の上げ直しで消す

- 日付: 2026-11-27
- 出典: ADR-0064（[adr/0064-tray.md](../adr/0064-tray.md)）決めたこと 9 の細部「残すのは最新のバージョンの中身だけである」の実装。Cloudflare の tray をデプロイの手順に載せた変更で決めた

R2 のキーは報告の id と中身の sha256 の組なので、上げ直すたびに前のバージョンの中身が R2 に残る。アップロードの口は、報告を新しいバージョンにしたあと、その報告の id の下の中身のうち、今のバージョンでなく、R2 に置いてから 1 日（24 時間）を過ぎたものを消す。消すのは同じ報告を次に上げ直したときだけで、定期の掃除（cron）は置かない。消すのに失敗しても上げ直しは成り立たせ、次の上げ直しで消し直す。

同じ報告への上げ直しが重なり、片方が 1 日より前の中身へ戻すと、その中身は消す候補に入ったまま D1 の指す物になりうる。R2 の削除には条件を付けられないので、両方の側で置き直す。掃除は中身を読んでから消し、消したあとで D1 を読み直して、指す物を消していたら読んだ中身を置き直す。上げ直しは D1 を切り替えたあとに中身が R2 に在るかを確かめ、無ければ置き直す。どの順で重なっても、後に動いた側が消えたのを見る。同じ中身の出し直し（バージョンを上げない）も、R2 に無ければ置き直す。

理由: 一覧の面が渡す署名付き URL は 5 分で切れるので、開いていた前のバージョンは数分で読めなくなる。1 日おけば、上げ直しの直前に開いた URL と、同時に走った上げ直しが新しく書いた中身を消さない。上げ直されない報告に古い中身は無く、cron を置くほどの量は残らない。

捨てた案:

- **上げ直しのたびに、前のバージョンの中身をすぐ消す**: 同時に 2 つ上げたとき、後から D1 に書いた側が、先に R2 に書いた側の中身を消し、一覧の面が指す中身が無くなるおそれがある。
- **R2 のライフサイクルの規則で消す**: 規則は日数で全部の中身に効くので、上げ直されない最新の中身まで消す。
- **cron の Worker で消す**: 4 つ目の Worker と時刻の設定が要り、上げ直しのときに消すのと比べて残る量が変わらない。
