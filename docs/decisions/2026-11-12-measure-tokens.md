# measure に課題ごとのトークン数を足す

- 日付: 2026-11-12
- 出典: 課題 A-0054（A-0007「任せきりの run にターン数・コストの上限を掛けられるか」の候補 c13。上限を考える前に「測る」）

`andon measure` に、課題ごとのトークン数を足した。`--json` は `tokens`（[contract.md](../contract.md) §13・`schema/measure.schema.json`）で、人向けの表は効率と通知の間の「トークン」の節（課題ごとに1行）。新しい記録は足さない。担当とレビュアーのセッションの記録（Claude Code・Codex が自分で書くもの）を読むだけで、書き換えない。

ここで置いたこと:

- **どの課題を出すか**: 期間に `log.jsonl` の行がある課題。レビュアーの課題も出す（レビューもトークンを使うため）。流れと効率の数えではレビュアーの課題を除くが、トークンの節では除かない。
- **数は課題の記録の全体**（期間で切らない）。知りたいのは「1つの課題にどれだけ掛かったか」で、上限を掛けるかを考える単位も課題だから。期間は、どの課題を出すかだけを決める。
- **どの記録を引くか**は `profile` のブランドで決める。Claude Code は `issue.yaml` の `session` の記録と、そのサブエージェントの記録。Codex はセッションの id を台帳に残していないので、先頭行の `cwd` が課題の場所（台帳の `issues/<id>/` か `worktree`）の rollout を全部引く。どちらの場所もその課題だけのものなので、ほかの課題の記録は混ざらない。
- **重なりを除く**: Claude Code は content block ごとに同じ `usage` の行を並べるので、`requestId`（無ければ `message.id`）ごとに1回だけ数える。Codex の `total_token_usage` は積み上がった数なので、rollout ごとに最後の値を取り、起き直しで分かれた rollout どうしは足す。
- **4つに分ける**: 入力（キャッシュを読み書きしなかった分）・出力・キャッシュ読み・キャッシュ書き。Codex の `input_tokens` はキャッシュの分を含むので、それを引いて入力にする。出力は Codex の推論の分を含む。
- **記録が無い課題は `usage: null`**（表は「記録なし」）で、0 とは分ける。`session` の無い課題（セッションを台帳に残す前に起きた課題）、記録が消えた課題が当たる。
- **ドルに直さない・上限を掛けない**。単価表は持たない。上限と止め方は Chief Engineer で別に詰める。
- **読めない行は飛ばした記録に出す**（`claude/<session>.jsonl`・`codex/<rollout の名前>` の形。記録の置き場の絶対パスは書かない）。数えから黙って落とさない。

分かっている限り: `andon issue resume --fresh` で `session` を新しくした課題は、前のセッションの分を数えない（台帳に残っているのは今の `session` だけ）。
