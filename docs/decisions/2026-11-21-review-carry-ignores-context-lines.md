# レビューの引き継ぎで比べる PR の差分は、消した行の並びと足した行の並びを囲みの行つきで比べ、前後のコンテキストの行は比べない

- 日付: 2026-11-21
- 出典: 振り返りが拾った繰り返し。rebase のあと PR が足した行と消した行は同じなのに、レビューを引き継がずに頼み直し、レビューの回を1つ使った PR が2件あった（mitaku/andon#407・mitaku/andon#418）。1件は main の別の PR が、PR の変えた表の行の近くの行の語を替えた。もう1件は rebase で衝突を解き、main が PR の書き換えた2行の間に足した行を残した。どちらも担当が `git range-diff` で PR の変更が同じことを確かめていた。
- 覆す: [2026-11-20-review-carry-same-patch.md](2026-11-20-review-carry-same-patch.md)

照合（`ledger.CheckReview`）がレビューを今の head に引き継ぐかを決める「PR の差分が同じ」を、次のように改める。

- 差分はコンテキストを 0 行で取る（`-U0`。hunk を繋げる設定も `--inter-hunk-context=0` に固定する）。
- 比べるのは、ファイルごとの見出し（`diff --git` の行・`---`・`+++`・mode の行・バイナリの中身）と、消した行の並びと、足した行の並び。空白も含めて比べる。「No newline at end of file」の行は直前の行に付けて比べる。
- 消した行と足した行には、それぞれ git が hunk の見出しに出す囲みの行（関数の宣言の行など。git の funcname）を添えて比べる。足した行を同じファイルの別の関数へ移したときと、main が囲みの行を変えたときは、引き継がない。
- 消した行と足した行を分けて並べるので、main が PR の変えた行の間に行を足して、消す・足すの組が割れても同じになる。
- hunk の行番号と、index の行と、前後のコンテキストの行は比べない。コンテキストの行は main の側の文で、main が近くの行を変えると、PR の変更が同じでも変わる。
- 衝突を解いた rebase でも、PR が足した行と消した行が同じ囲みの中で同じなら引き継ぐ。解いて足した行か消した行が変わったら、今までどおり `stale` になる。
- PR の差分の取り方（merge-base から commit までの `git diff --binary --full-index --no-renames`）、同じとみなさない場合（worktree・commit・`origin/HEAD` が無い、差分が空）、`git patch-id` を使わないこと、記録の `review.commit` と指摘の数え方は、覆した決定のまま変えない。

引き受けたリスク:

- main が変えた近くの行によって PR の行の意味が変わっても、レビュアーはその組み合わせを見ないまま引き継ぐ。覆した決定が引き受けた「main 側の変更と組み合わさって初めて壊れる場合」と同じ種類で、そこは CI と gate の checks が見る。
- 衝突を解くときに、足した行を同じ囲みの中の別の場所へ置いても引き継ぐ。囲みより細かい位置は、コンテキストの行でしか分からない。
- 囲みの行は git の既定の見つけ方（行の頭が英字か `_`・`$` の行）か、repo の `.gitattributes` が決める。囲みの行を持たない文書（表の行が続く Markdown など）では、ファイルの中の位置は比べない。

捨てた案:

- **コンテキストの行も比べる（覆した決定のまま）**: main が近くの行を変えただけで、PR の変更が同じでも頼み直す。
- **コンテキストの行も囲みの行も比べない**: 足した行を別の関数へ移した変更（たとえば認可の呼び出しを別の関数へ移す）を、レビュアーが見ないまま引き継ぐ。
- **衝突を解いた rebase は引き継がない**: 差分からは、衝突を解いた rebase と解かずに済んだ rebase を見分けられない。担当の申告で分けると、申告で gate を緩めることになる。
- **足した行のすぐ隣のコンテキストの1行だけを比べる**: main がその1行を変えると同じことが起き、何行なら十分かの決め手も無い。
