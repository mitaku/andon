# レビューの引き継ぎで比べる PR の差分は、足した行と消した行だけにし、前後のコンテキストの行は比べない

- 日付: 2026-11-21
- 出典: 振り返りが拾った繰り返し。rebase のあと PR が足した行と消した行は同じなのに、レビューを引き継がずに頼み直し、レビューの回を1つ使った PR が2件あった（mitaku/andon#407・mitaku/andon#418）。1件は main の別の PR が、PR の変えた表の行の近くの行の語を替えた。もう1件は rebase で衝突を解いた。どちらも担当が `git range-diff` で PR の変更が同じことを確かめていた。
- 覆す: [2026-11-20-review-carry-same-patch.md](2026-11-20-review-carry-same-patch.md)

照合（`ledger.CheckReview`）がレビューを今の head に引き継ぐかを決める「PR の差分が同じ」を、次のように改める。

- 比べるのは、ファイルの見出し（`diff --git` の行・`---`・`+++`・mode の行）と、足した行と消した行と、それに続く「No newline at end of file」の行だけ。空白も含めて比べる。
- hunk の見出し（`@@` の行）、index の行、前後のコンテキストの行と、コンテキストの行に続く「No newline at end of file」の行は比べない。コンテキストの行は main の側の文で、main が近くの行を変えると、PR の変更が同じでも変わる。hunk の見出しを除くので、コンテキストが変わって hunk が割れたり繋がったりしても同じになる。
- 衝突を解いた rebase でも、PR が足した行と消した行が同じなら引き継ぐ。解いて足した行か消した行が変わったら、今までどおり `stale` になる。
- PR の差分の取り方（merge-base から commit までの `git diff --binary --full-index --no-renames`）、同じとみなさない場合（worktree・commit・`origin/HEAD` が無い、差分が空）、`git patch-id` を使わないこと、記録の `review.commit` と指摘の数え方は、覆した決定のまま変えない。

引き受けたリスク:

- main が変えた近くの行によって PR の行の意味が変わっても、レビュアーはその組み合わせを見ないまま引き継ぐ。覆した決定が引き受けた「main 側の変更と組み合わさって初めて壊れる場合」と同じ種類で、そこは CI と gate の checks が見る。
- 衝突を解くときに、足した行を同じファイルの別の場所へ置いても、足した行と消した行が同じなら引き継ぐ。位置は前後のコンテキストの行でしか分からない。足した行を別のファイルに置いたときと、足した行の順が変わったときは引き継がない。

捨てた案:

- **衝突を解いた rebase は引き継がない**: 差分からは、衝突を解いた rebase と解かずに済んだ rebase を見分けられない。担当の申告で分けると、申告で gate を緩めることになる。
- **コンテキストの行を、PR が足した行のすぐ隣の1行だけ比べる**: main がその1行を変えると同じことが起きる。何行なら十分かの決め手も無い。
