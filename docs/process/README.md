# 仕事の流れと状態の定義（人が読む入口）

Chief of Staff の定常の仕事（ワークストリーム）と、もの（課題・担当・通知など）の状態の移り方を、ここに 1 本 1 ファイルで置く。決めたのは [ADR-0017](../adr/0017-process-definitions.md)（決めたこと 1・2・16）。

## 読み方

- このディレクトリの `README.md` 以外の `.md` は、`process/` の YAML から `andon process render` が作ったもの。1 本の定義が 1 ファイル（`<名>.md`）になる。
- ワークストリームのファイルは、目的・きっかけ・流れの図・手順の表（だれが、何を受けて、何を出すか）・機械がやる手順・AI がやる手順・数えるもの、の順。
- ステートマシンのファイルは、出所・状態の図・状態の表（どの記録の項目が持つか）・移り方の表（何が起きたら、だれが、2 回起きてはいけないか）、の順。

## 図の読み方

流れの図は BPMN の形をまねている（本物の BPMN ではない）。

| 形 | 意味 |
|---|---|
| 丸 | 出来事（きっかけ・終わり） |
| 角の丸い四角 | やること。色がやる者の種類（青: 機械〈dispatcher・ゲート・コマンド〉、緑: AI〈Chief of Staff・Chief Engineer・担当〉、黄: 人） |
| ひし形 | 分かれ道。枝の文字が、その道を行くとき |
| 横の帯 | やる者の種類 |
| 矢印の文字 | 前の手順が出すもの |

状態の図は、状態（四角）と移り方（矢印。文字は何が起きたら）。黒い丸は始まりと終わり。

## 記録との対応

- 状態の定義は、dispatcher の控え（`~/.local/state/andon/dispatcher/<slug>.json`）の一番上の項目を 1 つずつ、どれか 1 本の状態か「状態でない項目」（拾う位置とデータ）に割り当てる。項目を足す・消すときは定義も直す（テストが照らす）。
- 「2 回起きてはいけない」移り方は、「何が起きたら」の終わりに（§7.2 #番号）と書いて、[dispatcher.md](../dispatcher.md) §7.2「Nothing runs twice」の表の行（走らせる者・二重に走ったら・今の守り）を指す。

## 直すとき

1. `process/workstreams/<名>.yaml` か `process/states/<名>.yaml` を直す。形は `schema/process/` にある。決めた理由は ADR に書き、YAML には短い補足だけ。
2. repo の根で `andon process render` を打って、このディレクトリを作り直す。
3. 両方を同じ commit に入れる。`tests/process.sh` が、形と、作り直して差分が無いことを確かめる。

ここの `.md` を手で直さない（次に作り直したとき消える）。dispatcher は定義を読まない。定義と実装の食い違いはテストで見る。
