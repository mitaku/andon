## 問題（オーナーの言葉で。言い直しの段落）

オーナー（2026-11-19、Chief of Staff への発言）: 「このセル上でAndonを開発する上で、毎度イメージを焼き直すのは大変なので、イメージを焼き直したら消えたりすることを前提としてもよいので、それぞれのファイルを置き換えれるような仕組みを構築したほうがよさそう。」

言い直し（オーナーが 2026-11-19 に「合っている」と答えた）: このセルで Andon を直しながら使うとき、main にマージした直しを、ホストでの焼き直しとセルの作り直しを待たずに、このセルのエージェントに効かせたい。対象は skill・テンプレート・settings・hooks・`andon` と `kanban` のバイナリ。いまは焼き直しが重く、動いているエージェントも全部止まるので後回しになり、担当が古い決まりのまま働いている。差し替えは一時的でよく、次に焼き直したら消えてよい。マージ前の branch を試す使い方は、範囲の問いとして別に決める。

## 読んで分かった事実（2026-11-19。Andon を開発しているセルで実測）

1. セルの `/opt/andon` は1週間前に焼いたバージョンのままで、main と比べて `package/` の約30ファイル（skill 7本のうち6本・テンプレート7枚・`settings.json`・hooks 3本・`gate.json`・`environment.md` など）と `schema/` の8ファイルが食い違っていた。
2. 焼き直しはホストで `bin/bootstrap rebuild --from <checkout>` を打つ（[operate.md](../operate.md) の 3）。セルの中に docker は無い。コンテナを作り直すので、動いているエージェントの端末は全部止まる。
3. セルの利用者 `andon` はパスワード無しの sudo を持つ（`image/Dockerfile`）。`/opt/andon` は root の持ち物だが、コンテナの書ける層にあるので、セルの中から上書きできる。上書きはコンテナの再起動では残り、作り直し（`rebuild`）で消える。
4. セルの中で `mise exec -- go build ./cmd/andon` は通る（cache があれば2秒ほど）。
5. `ANDON_HOME=<checkout>/package` の口（[ADR-0001](0001-skills-distribution.md) 決めたこと 5）は一部にしか効かない: `schema/`（repo の根にある）と `bin/andon` は `package/` に無い。boot が置き換えるのはテンプレートと `writing.md` の中の `/opt/andon` だけで、skill の本文（`/opt/andon/writing.md` など）と `settings.json` の hooks・statusline のパスは `/opt/andon` を直に名指す。環境変数なので、その変数を持たないプロセス（compose が打つ `andon boot`・dispatcher・hooks）には効かず、コンテナの再起動で既定に戻る。
6. イメージの元の commit は、セルの中では `kanban --version`（commit の先頭12文字）で読める。`andon` にバージョンを出す口は無い。image の label（`org.opencontainers.image.revision`）はホストの `bin/bootstrap status` が出す。
7. 差し替えが効く時機は読む側で違う: hooks と `andon`・`kanban` は呼ばれるたびに実体を読む。テンプレート・managed settings・`CLAUDE.md` の3行・Codex の置き場は `andon boot` が生成し直したあと、次に起動するエージェントから効く。役の skill は `--append-system-prompt-file` で起動のときに system prompt に入るので、動いているエージェントには効かない。dispatcher は動いているプロセスなので、バイナリを替えたら起動し直しが要る。

## 前提（同意済み。番号）

オーナーが 2026-11-19 に 1〜5 すべてに同意。

1. 焼き直し（`bin/bootstrap rebuild --from`）を速くするのではなく、セルの中だけで完結する別の口を足す。焼き直しは今の形で残し、イメージが正のまま。
2. 何もしない選択は取らない。焼き直すまで直した決まりが担当に効かない状態（事実 1）は受け入れない。
3. 差し替えた状態は仮で、正はイメージ。差し替えたセルでは「どの commit から当てたか」がセルの中で読めなければならない。
4. この口は Andon を開発するセル（andon の repo の checkout を持つセル）のためのもの。利用者のセルがバージョンを上げる手段（`Dockerfile` の `FROM` を上げて `rebuild`）は変えない。
5. セルのコンテナが信頼の境界で、担当は既に sudo を持つ。`/opt/andon` をセルの中から上書きできること自体は新しい危険として扱わない。守る相手は間違える担当で、偽る担当ではない（[image.md](../image.md) の「残る危険」と同じ線）。

## 決めたこと（番号・日付・理由・捨てた案。あとから覆したら上書きせず下に足す）

1. **2026-11-19 形は「その場で上書き」。** 1つの commit から `package/` と `schema/` を `/opt/andon` に写し、`andon` と `kanban` を build して置き、`andon boot` を打ち直して dispatcher を起動し直す。
   理由: skill の本文・`settings.json` の hooks と statusline・テンプレートが `/opt/andon` を直に名指す（事実 5）ので、同じ場所を上書きする形だけが読む側を1つも直さずに済む。上書きはコンテナの作り直しで自然に消え（事実 3）、「焼き直したら消えてよい」に合う。
   捨てた案: 上書きの置き場を重ねて読む側が順に探す（ファイル単位で扱えるが、boot・テンプレート・hooks・skill の本文・plugin の読み込みを全部直すので大きく、漏れが出る）／commit ごとに完全なパッケージを組み `/opt/andon` を symlink にして切り替える（切り替えと戻しが一瞬だが、イメージの形が変わり、plugin の読み込みが symlink 越しで通るかの実測が要る）／`ANDON_HOME` を育ててセル全体を checkout に向ける（写しが要らないが、checkout の途中の状態〈branch の切り替え・rebase〉もセル全体に効き、間違える担当から守れない。`schema/` とバイナリは置き場が違う）。
2. **2026-11-19 当てる単位は、いつも1つの commit から全部（`package/`・`schema/`・`andon`・`kanban`）。** ファイルや種類を選んで当てる口は持たない。
   理由: skill は中で `andon`・`kanban` を打ち、schema で形を確かめるので、バージョンがずれると壊れる（[ADR-0001](0001-skills-distribution.md) の問題の段落）。全部を1つの commit から当てればバージョンが揃い、記録も commit 1つで済む。
   捨てた案: 種類（skill だけ・バイナリだけ）を選べる／ファイル単位で選べる（どのバージョンの組み合わせで動いているかが追えなくなる）。
3. **2026-11-19 当ててよいのは `origin/main` に含まれる commit だけ。** 既定は `origin/main` の先頭。中身は commit から取り出す（checkout の作業ツリーは読まない）。
   理由: 当てると `settings.json` の deny や hooks もセル全体で差し替わる。レビューとマージを通ったものだけをセル全体に効かせる。目的はマージ済みの直しを早く効かせること（問題の段落）。
   捨てた案: オーナーが明示したときだけマージ前の branch の commit も当てられる（dispatcher の直しをマージ前に本物で試せるが、レビュー前の決まりがセル全体に効く）／未 commit の変更を含む checkout をそのまま当てる（何が当たっているかを commit で言えなくなる）。マージ前の変更を試す口は今のまま: 自分の端末だけに効く `ANDON_HOME`（[ADR-0001](0001-skills-distribution.md) 決めたこと 5）と、ホストでの `rebuild --from`。
4. **2026-11-19 当てるのは Chief of Staff（自分の判断で）とオーナー。担当は当てない。** Chief of Staff は andon の PR がマージされたあと、時機を見て当て、オーナーに1行で知らせる。オーナーはいつでも当てられる。
   理由: 当てられるのは main の commit だけ（決めたこと 3）で、中身はレビューとマージを通っている。オーナーの手間を減らすのが目的。
   捨てた案: オーナーが言ったときだけ（Chief of Staff は食い違いを知らせるだけ。手間が残る）／dispatcher がマージのたびに自動で当てる（dispatcher が自分自身を入れ替える仕組みが要り、壊れた main がそのままセルに効く。再開の条件: 当て忘れで食い違いが残ることが続いたとき）。
5. **2026-11-19 道具は andon の repo の中のスクリプトで、イメージには入れない。** 置き場は `package/` の外（推奨は `image/build.sh` の隣。名前は担当が決めてよい）。当てる commit から取り出したスクリプト自身で当てる。Chief of Staff が当てる決まり（決めたこと 4）は、配る skill（`package/skills/`）ではなく、Andon を開発するセルの Andon プロジェクトの指針（セルの `projects/<slug>/AGENTS.md`）に書く。
   理由: andon の checkout を持つセルでだけ使え、利用者のセルには届かない（前提 4）。スクリプトと中身のバージョンが揃う。
   捨てた案: `andon` のサブコマンドにする（Go でテストしやすいが、利用者のセルに開発用の口が見える）。
6. **2026-11-19 動いているエージェントは止めない。道具は、古い skill のまま動いている端末の一覧を出すだけ。** 新しい skill・テンプレート・settings は次に起動するエージェントから効く。hooks と `andon`・`kanban` は当てた瞬間から全員に効く（事実 7）。起動し直すかどうかは Chief of Staff とオーナーが一覧を見て決める。dispatcher だけは道具が起動し直す（決めたこと 1）。
   理由: 作業の中断が焼き直しの痛みの中心（事実 2）で、それを残さない。
   捨てた案: 担当が動いていたら当てない（バージョンは混ざらないが、開発中のセルはたいてい誰かが動いていて当てる時機が無くなる）／当てたあと全員を起動し直す（揃うが中断する）。
7. **2026-11-19 見せ方は、記録1枚と、状態を出す口。** 当てるたびに、当てた commit・日時・イメージの元の commit を記録に書く（置き場は `/opt/andon` の中。作り直しで一緒に消える）。スクリプトは状態を出す口を持ち、イメージのバージョン・当てた commit（当てていなければ「当てていない」）・`origin/main` の先頭から何 commit 遅れているかを出す。Chief of Staff がそれを読んでオーナーに伝える。
   理由: 前提 3。配るパッケージのコードを増やさない。
   捨てた案: 各エージェントの画面の下の行（statusline）にも印を出す（いつでも目に入るが、配る `package/lib/andon/statusline` に開発用の表示が入る）／記録だけ（遅れに気づきにくい）。
8. **2026-11-19 イメージのバージョンへ戻す口を持つ。** 最初に当てる前に、イメージの `/opt/andon` と `kanban` を退避しておく（置き場はコンテナの中。作り直しで一緒に消える）。スクリプトは、退避からイメージのバージョンへ戻す口を持つ。戻したら記録を消し、`andon boot` を打ち直して dispatcher を起動し直す。戻す口は `andon`・`kanban` が壊れていても動く。
   理由: 壊れた main を当てて `andon` や dispatcher が動かなくなったとき、戻す口が無いとオーナーがホストで焼き直すまでセルが止まる。
   捨てた案: 戻す口を持たない（戻すのは焼き直しだけ）／1つ前に当てたバージョンへも戻せる（直前のバージョンも毎回退避するので道具が大きくなる。main を進めて当て直すか、イメージのバージョンへ戻せば足りる）。
9. **2026-11-19 価値の仮説を置く**（下の節）。
   理由: バージョンが混ざって担当が失敗する場合の撤退の線を先に持つ。
   捨てた案: 無し（利用者に見えない開発用の道具として、[ADR-0025](0025-formal-model-in-repo.md) と同じ扱いにする）。
10. **2026-11-19 イメージの備品のずれは、警告して当てる。** イメージの元の commit から当てる commit までの間に `image/` が変わっていたら、変わったファイルを並べて「焼き直しが要るかもしれない」と出し、当てるのは続ける。同じ警告は状態を出す口にも出る。
   理由: この口が当てるのは `/opt/andon` と `andon`・`kanban` だけで、イメージの備品（aqua の道具のバージョン・Claude Code のバージョン・bash の設定）は焼き直さないと変わらない。新しい道具を前提にした skill が当たると担当が失敗しうるので、知らせる。`image/` はバージョンアップでよく変わるので、止めると当てられない日が多くなる。
   捨てた案: 既定では断り、明示の指定で当てる（安全だが手間が増える）／何もしない（担当が失敗するまで気づけない）。

## やらないこと（範囲の外。理由）

- **マージ前の branch・未 commit の変更をセル全体に当てること**（決めたこと 3）。試す口は今のまま（`ANDON_HOME` と `rebuild --from`）。再開の条件: dispatcher やフックの直しを、マージ前に本物のセルで試せないことが直しの妨げになったとき。
- **ファイルや種類を選んで当てること**（決めたこと 2）。
- **マージのたびの自動の適用**（決めたこと 4 の捨てた案。再開の条件もそこ）。
- **動いているエージェントの起動し直し**（決めたこと 6）。道具は一覧を出すだけ。
- **イメージの備品を当てること**（`image/` の下で決まるもの: aqua の道具・Claude Code・Playwright・bash の設定・sshd）。焼き直しの仕事のまま（決めたこと 10 は知らせるだけ）。
- **ホストに効くものを届けること**。`/opt/andon/compose.yaml` と `/opt/andon/host/*` はセルの中で差し替わるが、ホストがそれを取り出すのは `bin/bootstrap`（`up`・`host-install`）のときで、取り出す元はイメージ。この口では届かない。
- **利用者のセルへ配ること・`andon` のサブコマンドにすること**（前提 4・決めたこと 5）。
- **`ANDON_HOME` の口を直すこと・やめること**。自分の端末だけで checkout を試す口として残す（事実 5 の穴は、この文書では塞がない）。
- **statusline への印**（決めたこと 7 の捨てた案）。

## 受け入れ条件（テストできる形。どの継ぎ目でテストするかを先に）

継ぎ目は2つ。

- **スクリプトの入口**（新しい `tests/<名前>.sh`。今ある `tests/*.sh` と同じく `tests/lib/` で切り離す）。スクリプトは、書く先の根（`/opt/andon`・`kanban` の置き場・退避の置き場）と、元にする repo を、環境変数か引数で差し替えられるようにする。検査は一時の置き場と、検査の中で作る試しの repo（`origin/main` を持つ）に向け、sudo を使わず、セルの本物に書かない。`andon boot` と hc は偽物に置き換えてよい（確かめるのは「呼んだこと」で、boot と dispatcher の中身は今ある検査が持つ）。`go build` は本物を走らせる。
- **Andon を開発するセルでの実測**（`package/` に効く変更はセルで実測する決まり。報告に command と出力を書く）。

下の `<道具>` はスクリプトの入口、`<根>` は検査が渡す一時の置き場。証拠は、条件ごとの command と、見る出力。

| # | 条件 | 走らせるもの | 見る出力 |
|---|---|---|---|
| 1 | `origin/main` の commit を当てると、`<根>` の中身がその commit の `package/` と `schema/` に一致し、`andon` と `kanban` が置かれる | `tests/<名前>.sh`（当てたあと `git archive <commit> package schema` の展開と `diff -r`） | `diff -r` が空（`bin/`・記録を除く）。`<根>/bin/andon help` が rc 0。`kanban --version` が当てた commit の先頭12文字 |
| 2 | 記録に、当てた commit・日時・イメージの元の commit が入る | 同上（記録を `jq` で読む） | 3つの値。イメージの元の commit は、最初に当てる前の `kanban --version` の値 |
| 3 | `origin/main` に含まれない commit は断る。作業ツリーの未 commit の変更は当たらない | 同上（試しの repo に main の外の commit を作って渡す。作業ツリーを汚して当てる） | rc が 0 でない・`<根>` が当てる前と同じ（`diff -r` が空）。汚した中身が `<根>` に無い（先に、汚した語が作業ツリーにあることを同じ所で確かめる） |
| 4 | 途中で落ちても半端にならない | 同上（`go build` が落ちる commit を main に置いて当てる） | rc が 0 でない・`<根>` と記録が当てる前と同じ |
| 5 | 状態を出す口が、イメージのバージョン・当てた commit・遅れを出す | 同上（当てる前、当てたあと、試しの repo の main を2つ進めたあとの3回） | 当てる前は「当てていない」とイメージのバージョン。当てたあとは当てた commit と遅れ 0。進めたあとは遅れ 2 |
| 6 | 戻す口で、イメージのバージョンに戻る | 同上（2回当ててから戻す。`<根>/bin/andon` を実行できないファイルに替えてから戻す、も） | `<根>` と `kanban` が最初の中身と一致（`diff -r` が空）・記録が無い・どちらの場合も rc 0 |
| 7 | 当てたあと・戻したあとに、`andon boot` を打ち直し、dispatcher を起動し直す | 同上（偽の `andon`・`hc` が呼ばれた引数を記録する） | `boot` の呼び出しと、dispatcher の端末を止めて起動する呼び出しが、置き換えのあとに1回ずつ |
