# ADR-0023: サイドバーに「あんどん」らしさを見た目で出す（仕様・設計。2026-11-12。Chief Engineer の課題 A-0163）

- 状態: **提案（2026-11-12）**。人が PR をマージした日が決定の日（[decisions/2026-11-12-adr-0023-sidebar-andon-look.md](../decisions/2026-11-12-adr-0023-sidebar-andon-look.md)）。実装は「依頼書に切る案」のとおり別の課題（切るのは Chief of Staff）。覆すときは新しい ADR を書き、この行を `覆された → ADR-NNNN` にする。小さな改めは「決めたこと」に下から足す。
- 主題: Andon 同梱の App のレイアウト `andon` の左の列（サイドバー）の見た目。働き（何を出すか・並び・キー）は [ADR-0015](0015-inbox-needs-you.md) のまま変えない。
- 語は [design.md](../design.md) §0.1。この題は新しい約束（端末のラベル・schema・台帳の形）を足さない（前提 3）。
- 入力: 依頼書 A-0163（人の発言 2026-11-12 と Chief of Staff の経緯）、`package/host/inbox/`（main.js・README.md・RECIPE.md）、`package/host/layouts/andon.json`、[design.md](../design.md) §1.1・§6 問い1（モチーフ）、[assets/logo/README.md](../assets/logo/README.md)（ロゴの色と形）、[vision.md](../vision.md) §3（灯りの言い方）、[ADR-0002](0002-herdr-spaces.md) 決めたこと 18、[ADR-0015](0015-inbox-needs-you.md)、Herdr App の mod guide と同梱の `workspace-chrome`（出典の節）。

## 問題（人の言葉で。言い直しの段落）

人（2026-11-12、Chief of Staff への発言）: 「Modのサイドバーがかなりよいなと思いました。ここが「あんどん」らしさが見た目にでてくるとよりよさそうです。（今でもあんどんらしさはあります）」

言い直し（人が同意 2026-11-12）。サイドバーは今の中身と並び（Inbox の Needs you と Projects・Spaces・フッター）のままで役に立っている。変えたいのは働きではなく見た目。いまは「灯りは人を呼ぶときだけつく」という Andon の考えが並べ方には出ているが、色や形は Herdr の標準を借りたまま。ひと目で「Andon の画面だ」「灯りがついた＝自分が呼ばれている」と分かる見た目にしたい。

事実（人に聞かず読んで確かめたもの）:

- サイドバーは上から brand（46px。Herdr のロゴと「Herdr」の字・検索・列を畳むボタン）→ Inbox → Spaces → フッター（Settings・Add machine）→ 名前付けの block（1px）。Andon が描いているのは Inbox と名前付けの block だけで、brand・Spaces・フッターは App 同梱の mod（`workspace-chrome`・`spaces`）。同梱の mod は読むだけで、変えるには複製して自分の mod にする（mod guide）。
- モチーフは決定済み（design.md §6 問い1）: 意味は三色ランプ（緑＝流れている・黄＝人の判断待ち・赤＝止まった）、絵は行燈。ロゴ「A の行燈」は窓の色が状態の印で、琥珀 `#F0A202`／`#FFD36B`・緑 `#2F9E62`／`#8FD8AE`・赤 `#D8453B`／`#F29A92`（assets/logo/README.md）。
- いまの Inbox は、Needs you の見出し・バッジ（Permission・Question・Auth・Failed・Reply）を全部テーマの `blocked` 色の1色で塗る。役のアイコンは `accent` 色。Andon の灯りの色はどこにも使っていない。
- mod が知っているのは端末の状態（`working`・`blocked`・`done`・`idle`・`error`）と報告の `kind`（permission・question・auth）だけ。問いが呼び出しか定位置停止か（vision.md §3）は知らない。
- 見た目を変える手段は3つ: (a) Inbox の描き方、(b) レイアウトの根の `theme`・`colors`（窓全体に効き、App 同梱の mod と端末にも及ぶ。今は根の見た目だけが効く。人がテーマを選ぶとそちらが勝つ）、(c) brand の block を Andon の mod に差し替える。mod は動き（`.loop("opacity", …)`・`.spin`）も描ける（タイマーで描き直さない）。
- レイアウトの見本の絵 `package/host/layouts/andon.svg` は ADR-0015 より前の Inbox（Focus・Done・Working・Settled）を描いたままで古い。

## 前提（同意済み。番号）

人が 2026-11-12 に 1〜4 に答えた（2 は人の指摘で直した）。

1. サイドバーの働きは変えない。Inbox が出すもの（Needs you と Projects の2節。ADR-0015）・行の並び順・クリックやキーの動きはそのまま。変えるのは色・形・絵・動きだけ。
2. 新しいモチーフや色は作らない。決定済みのモチーフと、いまあるロゴの色と形をサイドバーに持ち込む。ただし「黄＝人の判断待ち・赤＝止まった」の定義のままでは Needs you の行を塗り分けられない（人の指摘「今だと黄色と赤がそういう意味だと同じ状態だね」。`blocked` の端末は人を待っていて、かつ止まっている）ので、サイドバーでの当て方はこの文書で決め直す（決めたこと 1）。
3. 何もしなくても困らない（今のサイドバーで仕事は回る）。「より良く」の題で急ぎではない。小さく入れ、合わなければ元の見た目に戻せる形にする。端末のラベル・schema・台帳などの約束は足さない。
4. 配り方は今のまま: `package/host` に同梱し `host-install` が人の App の設定フォルダに置く。人自身の設定（`settings.json`・`keys.json`・自分で選んだテーマ）には書かない。`host-install` は既存のファイルを上書きしないので、新しい見た目にするときは人が手元で mod とレイアウトを退避して置き直す手が1回要る（operate.md「Herdr App の mod とレイアウト」）。

## 決めたこと（番号・日付・理由・捨てた案。あとから覆したら上書きせず下に足す）

1. **2026-11-12 サイドバーでの灯りの色: 琥珀＝人が答えれば進む行（Permission・Question・Auth・Reply）、赤＝ターンが失敗して止まった行（Failed）。**
   理由: 人の手が違う（答える／調べて直す）。mod が今読める状態だけで分けられ、新しい約束が要らない。Failed は今もバッジの字で分けている。
   捨てた案: 灯りは琥珀の1色だけ（Failed はバッジの字だけで区別。赤をサイドバーで使わなくなる）／呼び出し＝琥珀・定位置停止＝赤（vision.md §3 にいちばん正確だが、mod が問いの種類を知る口〈ラベルか台帳の読み取り〉を新しく足すことになり、前提 3 を越える）。

2. **2026-11-12 出す場所は2つ: Inbox の Needs you と、サイドバーの一番上（brand）。** Inbox は Needs you の見出し・バッジ・印を決めたこと 1 の色で塗る。brand は Herdr のロゴと字を Andon の記号（A の行燈）に替え、窓の色でサイドバー全体の状態を示す（決めたこと 3）。検索と列を畳むボタンは今のまま残す。brand は App 同梱の `workspace-chrome` の brand を写した Andon の mod が描く（同梱の mod は読むだけなので。files-plus と同じ持ち方で、App が brand を更新しても自動では追わない）。
   理由: 言い直しの2つの目的に1つずつ当たる（「Andon の画面だ」＝一番上の行燈、「灯りがついた」＝Inbox の色）。
   捨てた案: A「Inbox の中だけ」（いちばん小さく安全だが、一番上は Herdr のロゴのままで「Andon の画面だ」が弱い）／B＋C「レイアウトが色かテーマを持ち、Spaces・tab・端末の枠にも効かせる」（人が選んだテーマの色より Andon の色が勝つ。効き方は実測が要る）／C だけ「レイアウトの色」（琥珀と赤を分けられず、行燈の絵も出ない）。

3. **2026-11-12 行燈の窓の色: Needs you に Failed が1つでもあれば赤、無くて答え待ちの行があれば琥珀、人を呼ぶ行が1つも無ければ消灯（窓を暗くする）。消灯は「一旦」（人の言葉「一旦１の消灯するでやってみましょう」）。** 緑はサイドバーで使わない。働いている印は今の回る輪のまま。
   理由: 「灯りは人を呼ぶときだけつく」をそのまま絵にする。ついた瞬間がいちばん目立つ。
   捨てた案: 緑に灯す（三色ランプどおりだが、いつも何かの色がついていて「ついた＝呼ばれた」が色の変わり目だけになる）／働く役がいれば緑・いなければ消灯（「Working にはあまり興味がない」〈ADR-0015〉と逆向き）。観察（価値の仮説）のときに見直す。

4. **2026-11-12 動き: 行燈の色が変わるときだけゆっくり移り変わり、あとは静かに灯り続ける。明滅しない。**
   理由: 人は隣の端末で作業していることが多い。視界の端で動き続けるものは邪魔になる。音と通知は Herdr が別に出す（mod は出さない。ADR-0015 決めたこと 5 のまま）。
   捨てた案: ついている間ゆっくり明滅（見逃しにくいが、長く待たせている間ずっと動く）／動き無し（即座に切り替わるだけ）。

5. **2026-11-12 進め方: 作って、見て、直す。** この文書の方向で実装してマージし、人が手元に置き直して見る。見ないと決まらない細部は担当がロゴの色から仮に決め、人が見て違うと言ったところを小さな直しの課題にする。捨てる試作は先に作らない。
   理由: 実際の画面は人の手元でしか見られず、試作でも置き直しの手が同じだけ要る。約束に触れないので、戻すのは前の版を置き直すだけ（前提 3）。
   担当が仮に決める細部（人が決めたことではない。見て直す対象）:
   - 色の値はロゴのもの（琥珀 `#F0A202`／`#FFD36B`・赤 `#D8453B`／`#F29A92`）を固定で使い、Needs you の灯りにテーマの `blocked` 色は使わない。琥珀を文字の色にするか地の色にするか・濃さは、明るいテーマと暗いテーマの両方で読める方を選ぶ。
   - Needs you の見出しの色、バッジの「Needs you」（種類の無い `blocked`）は琥珀の側。
   - 行燈の大きさ、記号の横に置く字（「Andon」）、消灯の窓の暗さ、移り変わりの長さ。
   - 列を細く畳んだとき（44px）に行燈を出すか。畳むボタンと並んで収まらなければ出さない。
   - 記号の色の替え方（ロゴの SVG は CSS の変数で塗っているが、App の `svg()` は1色で塗る。枠と窓を分けて重ねるか、状態ごとの絵を持つか。未確認なので実測する）。
   - brand を描く mod を新しく足すか、既にレイアウトにいる `andon` の mod に持たせるか。
   捨てた案: 先に捨てる試作を見てから文書を確定する（確実だが1往復ぶん遅い）。

## やらないこと（範囲の外。理由）

- **サイドバーの働きを変えること**（前提 1）。Inbox の節・行の中身・並び・キー・「mod は何も書かない」は ADR-0015 のまま。
- **レイアウトの根に `theme`・`colors` を持たせること、Andon のテーマを配ること**（決めたこと 2 の捨てた案 C）。Spaces・tab・フッター・端末の色は人が選んだテーマのまま。フッター（Settings・Add machine）と Spaces は App 同梱の mod のまま触らない。
- **呼び出しと定位置停止を色で分けること**（決めたこと 1 の捨てた案）。mod が問いの種類を知る口（端末のラベル・台帳の読み取り）は足さない。
- **緑・明滅・音・通知**（決めたこと 3・4）。
- **役のアイコン（Chief of Staff＝`clipboard-list`・Chief Engineer＝`drafting-compass`、`accent` 色）を変えること**。今のサイドバーは良いと人が見ている（依頼書 A-0163）。ADR-0002 決めたこと 18 のまま。
- **kanban-board・context-header・files-plus の色を揃えること**。この題はサイドバーだけ。揃えたくなったら別の題。
- **人の設定（`settings.json`・`keys.json`・選んだテーマ）を `host-install` が書き換えること、既存の mod・レイアウトを上書きすること**（前提 4）。
- **dispatcher の記号（提灯）をサイドバーに出すこと**。dispatcher は人と話す役ではない（ADR-0015 決めたこと 4）。

## 受け入れ条件（テストできる形。どの継ぎ目でテストするかを先に）

継ぎ目は 3 つ。新しい継ぎ目を作らない。

1. **`tests/host/screen.mjs`（偽の herdr API で mod を読み込む。既にある）**:
   - Inbox の Needs you の行の灯りの色: `blocked`（報告の `kind` が permission・question・auth・無し）と役の Reply は琥珀の側、`error`（Failed）は赤の側。偽の `theme()` の `blocked` にロゴと違う色を渡しても、灯りの色はそれにならない。
   - 行燈の状態: Needs you が空なら消灯、答え待ちだけなら琥珀、Failed が1つでもあれば赤。Inbox と同じ入力から同じ判定になる（ペインの無い役の「見た」〈ADR-0015 決めたこと 7〉を含む。Inbox が Reply を出さないとき行燈も灯らない）。
   - ADR-0015 と ADR-0002 決めたこと 18 の既存の検査（節は 2 つ・役ごとのアイコン・settle とボードのダイアログが無い・`hc` を呼ばない）が通ったまま。
   - レイアウト `andon`: brand の block が Andon の mod を指す。根に `theme`・`colors` が無い。名前付けの block（`andon-names`）と `sidebar-footer`（`workspace-chrome` の `footer`）が残る。
   - 描き直しのためのタイマーを足していない（移り変わりは App の `.transition`。今ある 30 秒のタイマーは待ち時間の表示用でそのまま）。
2. **文書と配り方（`tests/public.sh`・`tests/andon-init.sh`・`tests/run --changed`）**: 新しい mod を足したなら `host-install` がそれを置き、`docs/operate.md` の mod の表・数・置き直しの手順 8 が合っている。`package/host/inbox/README.md`・`RECIPE.md` が新しい色を書く。App 同梱の `workspace-chrome` から写した部分は、その mod の README に Origin と Licence の節を持つ（files-plus と同じ）。レイアウトの見本の絵 `package/host/layouts/andon.svg` が今の姿（Needs you・Projects・一番上の行燈）になっている。
3. **人の手元で目視（人にしかできない。App は人のマシンで動く）**: `host-install` で置き直した App で、`herdr-app check` が Andon の mod に通る。明るいテーマと暗いテーマの両方でバッジと見出しが読める。呼ぶ行が無いと行燈は消灯で、Chief of Staff の返事が来ると琥珀にゆっくり変わり、見ると消灯に戻る。検索と列を畳むボタンが今までどおり働く。
