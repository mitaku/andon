# ADR-0029: 工場の2つの面を言い分ける（セルは場所、Andon はしくみ）（仕様・設計。2026-11-19）

- 状態: **決定（2026-11-19）**。人が対話の中で「用語だけ決める」と言った（[decisions/2026-11-19-adr-0029-factory-place-and-mechanism.md](../decisions/2026-11-19-adr-0029-factory-place-and-mechanism.md)）。実装は「依頼書に切る案」のとおり別の課題（切るのは Chief of Staff）。覆すときは新しい ADR を書き、この行を `覆された → ADR-NNNN` にする。小さな改めは「決めたこと」に下から足す。
- 主題: 「工場」という語が Andon とセルのどちらを指すか。Andon とセルの定義の文。外に向けた一文の「software factory」の扱い。同じ対話で出た Chief of Staff の単位の題は [ADR-0031](0031-cell-chief-of-staff.md)（提案）に分けた。
- 語は [design.md](../design.md) §0.1。

## 問題（人の言葉で。言い直しの段落）

人（2026-11-19）: 「Andon の SoftwareFactory 部分は少し定義の再構築が必要かも、やることは変わらないのだけれども工場（CELL）としての境界を作り、規律を作るものだと思った」「主語の問題だと思っている。Cell=工場だし、Andon=工場ではある。Cellは境界・空間で、Andonは工場のしくみというイメージ」「選択的DarkFactoryKitであり、HomeRepo（Matt Pocock氏命名）なんだよね」「Kitというのも変だし、セルと言う用語が必要なのかというと悩ましい。用語整理だけでもいいかも」。

言い直し: Andon を外に説明する一文の「software factory」の部分を組み直したい。Andon がすることは変えない。実体は2つに分けて言える。1つはセルで、Home Repo をコンテナに入れて境界を引いたものである。指針と skill と wiki がそこにあり、作業はいつもそこから始まる。これが工場の場所の面にあたる。もう1つは Andon で、その場所を選択的 Dark Factory にするしくみである。パッケージと約束と文書を配り、中で守る規律を作る。困っているのは2つ。いまの「一人用のソフトウェア工場」という言い方では、この実体が外の読み手に伝わらない。そして文書の中で「工場」が指すものが文ごとにぶれている。

いまの文書にある言い方（2026-11-19 の main）:

| 所 | 文 | 「工場」が指すもの |
|---|---|---|
| [design.md](../design.md) 冒頭の人の決定（2026-11-04）・§0.1・用語集 | Andon は工場そのもの。構造の名前 | Andon |
| README「セルの考え方」 | Andon は一人のソフトウェア工場で、セルはその中の持ち場にあたる | Andon。セルは工場の一部 |
| README「セルの考え方」 | 根は工場全体に1つではなく、セルごとに1つある | セルの集まり |
| 用語集「プロジェクト」 | セルの中の持ち場1つ | 「持ち場」がプロジェクトを指す。README ではセルを指す |
| [ADR-0005](0005-cell-repo.md) 前提 1 | 台帳は工場の中の工程の記録 | セル1つ |

Home Repo の出どころ: Matt Pocock「The Home Repo Pattern」（2026-11-12）。定義は「skill と AGENTS.md と共有の文書を持つ1つの repo。エージェントはそこで起動し、ほかの repo はそこから指して clone する」。CI や software factory で使うときは Home Repo を sandbox に入れる、と書いている。セルの repo は同じ形をしている（指針・skill・wiki を持つ。案件の repo は `.ghq/` に clone して git の外に置く。課題ごとに worktree を切る）。違いは2つ。Home Repo は repo だけを指し、コンテナの境界を含まない。Home Repo は全部を1つに集めるが、セルは信頼の境界ごとに分けて複数立てる。

## 前提（同意済み。番号）

1. 「Andon は工場そのもの」（人の決定 2026-11-04）は覆さない。足すのは、どの面の名前かという説明（人 2026-11-19「Andon=工場ではある」）。
2. 識別子・コマンド・repo 名・schema を変えない。変わるのは定義の文。

## 決めたこと（番号・日付・理由・捨てた案。あとから覆したら上書きせず下に足す）

1. **2026-11-19 「セル」の語と識別子（`cell`・`<slug>-cell`）は残し、定義の文を直す。** セルは工場の場所の面で、境界と空間。信頼の境界ごとに1つ立て、セルの repo と、それを入れるコンテナでできている。セルの repo が Home Repo に当たる。
   理由: Home Repo は repo だけを指し、コンテナの境界と「信頼の境界ごとに複数立てる」を含まない。セルの語は repo の約 980 行に出て、`andon init` とホストの起動スクリプトが repo 名 `<slug>-cell` を前提にしている。2026-11-06 に「建屋」から替えたばかり。
   捨てた案: 文の語だけ Home Repo に替える（文の語と識別子がずれ、コンテナの境界を指す語が無くなる）。識別子ごと替える（約 980 行と動いているセルの repo 名に及び、「やることは変えない」を越える）。

2. **2026-11-19 表示名「Andon — a one-person software factory」は残し、その直後の説明文を、場所（セル）としくみ（Andon）の2つの面で組み直す。** repo の description・social preview の画像・topics は触らない。
   理由: 表示名は同じ名前の別のものと見分けるための修飾（人の決定 2026-11-06）で、その役は果たしている。困っているのは名前そのものではなく、名前のあとに境界と規律という実体の説明が無いこと。
   捨てた案: 表示名を「a selective dark factory for one person」に替える（2026-11-06 の決定を覆し、description・画像・topics を作り直す。selective dark factory は英語の読み手に説明が要る）。表示名から factory を外す（設計書の工場・ライン・セルの語彙と表示名が離れる）。

3. **2026-11-19 用語集の定義を3か所直す。「工場」の項は足さず、書き分けの決まりも置かない。「Kit」は語として足さない。**
   - Andon: 工場そのもの。工場のしくみの面の名前で、境界の中で守る規律を指す。規律は役・工程・ゲート・約束。場所の面はセル。部品の名前には使わない。
   - セル: 工場の場所の面。境界と空間。信頼の境界ごとに1つ立てる長寿命のコンテナと、その中に入るセルの repo（`<slug>-cell`）でできている。手元にもクラウドにも立つ。
   - セルの repo（新しい項）: セルの根の git の repo。指針・skill・wiki を持ち、作業はここから始まる。外の語では Home Repo に当たる。
   理由: 「Andon は工場そのもの」（人の決定 2026-11-04）は覆さず、どの面の名前かを足す。配るものを指す語は既に「パッケージ」があり、人も「Kit というのも変」と言った。
   捨てた案: 「工場」の項を足し、場所を言うときはセル、しくみを言うときは Andon と書く決まりにする（人が選ばなかった）。Home Repo を用語集に書かず README でだけ触れる（人が選ばなかった）。

## やらないこと（範囲の外。理由）

- 表示名・repo の description・social preview の画像・topics を変えること（決めたこと 2）。
- 「セル」の語と識別子を改名すること（決めたこと 1）。
- 「工場」「Kit」を用語集の項にすること（決めたこと 3）。
- 用語集の「プロジェクト」の定義を直すこと。Chief of Staff の単位が決まると変わるので、[ADR-0031](0031-cell-chief-of-staff.md) の側で扱う。
- [vision.md](../vision.md) と、過去の ADR・決定の記録の本文を書き換えること。上書きしない決まりなので、本文はそのまま残す。

## 受け入れ条件

継ぎ目は、grep と既存の文書の検査（`tests/package.sh`・`tests/words.sh`・`tests/public.sh`）。証拠は、走らせた command と出力のパスを報告に書く。

- A1. 用語集（`package/skills/glossary/SKILL.md`）の Andon・セル・セルの repo の定義が、決めたこと 3 の文になっている。証拠: `grep -n '場所の面\|しくみの面\|Home Repo' package/skills/glossary/SKILL.md` が3行以上当たる出力と、`tests/package.sh`・`tests/words.sh` が通った出力。
- A2. README の表示名の行が残り、直後の説明が場所としくみの2つの面で書かれ、セルを「持ち場」と呼ぶ文が無い。英語の要約も同じ定義になっている。証拠: `grep -c 'Andon — a one-person software factory' README.md` が 1 以上。`grep -n 'その中の持ち場' README.md` が空（この grep が当たりうることは、直す前の main で同じ grep が1行当たることで確かめる）。`tests/public.sh` が通った出力。
- A3. [design.md](../design.md) §0.1 の Andon とセルの行が同じ定義になり、冒頭の人の決定に 2026-11-19 の行が足されている。証拠: `grep -n '2026-11-19' docs/design.md` の出力。
