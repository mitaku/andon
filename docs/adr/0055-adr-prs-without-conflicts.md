## 問題（オーナーの言葉で。言い直しの段落）

オーナーの言葉（2026-11-22）: 「ADRがコンフリクトしてるので解消させてください（これは作りを見直さないといけないね」。

Chief Engineer が同時に何人も ADR を書くと、その PR が互いに衝突する。1 本がマージされるたびに、残りの PR がマージできなくなる。Chief Engineer の文書の PR はいつもオーナーがマージするので、そのたびにオーナーが直しを頼むことになる。今の衝突を 1 本ずつ直すのではなく、並べて書いても衝突しない作りに変える。

確かめた事実（2026-11-22。数えたのは main の `fe13016` まで。日付は UTC）:

1. **衝突する所は 1 か所。** `README.md` の ADR の一覧である。2026-11-22 に開いていた PR #484（ADR-0047）と、そのときの main（`7f5e233`）を `git merge-tree` で合わせると、衝突するファイルは `README.md` だけだった。PR #476（ADR-0050）は main とは衝突しなかったが、#484 とは `README.md` で衝突した。片方が入ると、もう片方がまた止まる形だった。2026-11-22 の 1 日に出た ADR の PR 8 本のうち 3 本（#476・#479・#483）が、main を取り込んで一覧の行を揃える commit を計 6 本持つ。#476 は 4 回取り込んだ。
2. **ADR の PR は必ず一覧に触る。** `tests/adr-index.sh` は、全部の ADR に一覧の行を求め、行の状態の語が ADR の状態行と同じことを見る（[ADR-0033](0033-adr-inventory-and-slimming.md) 決めたこと 6）。この検査を決めた ADR-0033 から、ADR を足した commit は 20 本とも `README.md` に 1 行足している。2026-11-18 からの main の 224 commit のうち、一覧の行を足すか変えた commit は 25 本ある。
3. **足す所が同じ。** 新しい ADR の行は一覧の末尾に足す。写しで試すと、末尾に 1 行ずつ足した 2 本は衝突し、離れた所に番号の順で足した 2 本は衝突しない。
4. **ほかに必ず重なるファイルは無い。** ADR を足した commit が触ったファイルを、2026-11-19 からの分で並べた。ADR-0033 からの 20 本に共通するのは `README.md` だけだった。ADR の本文と決定の記録は 1 件 1 ファイルである。古い ADR を覆す PR はその ADR の索引に触るが、毎回ではなく、行も別である。
5. **一覧を別のファイルへ移しても同じ。** [ADR-0046](0046-readme-for-first-time-readers.md) 決めたこと 9 は、一覧を `docs/adr/README.md` に移すと決め、払うものに「一覧が 1 ファイルである限り、並んで走る ADR の PR は同じ所に行を足してぶつかる。これは移す前と変わらない」と書いている。この引っ越しはまだ実装していない。
6. **同じ問題を片付けた前例が repo にある。** 決定の記録は 2026-11-07 から 1 件 1 ファイルで、一覧のファイルを作らない（[decisions.md](../decisions.md) の冒頭。「作れば、それが次のぶつかる所になる」）。`CHANGELOG.md` は PR ごとには触らず、バージョンを切るときだけ書く。
7. **GitHub は union のマージを見ない。** `.gitattributes` に `merge=union` を書くと、手元の git は末尾に足した 2 本を衝突させずに両方の行を残す。GitHub の PR のマージはこの指定を見ない。GitHub の文書に記述は無く、GitHub Community の要望（2021-12 から開いたまま）には、2026-10 まで「効かない」という報告が続いている。
8. **番号の重なりは、git も検査も気づかない。** ファイルの名前は `NNNN-<英字の短い名前>.md` なので、同じ番号でも名前が違えば git は衝突と言わない。同じ番号 0052 の ADR を 2 本にした写しで `tests/adr-index.sh` を回すと、通った。main の ruleset は、マージの前に最新の main で検査を回し直すことを求めていない。
9. **番号は手順だけで守っている。** `AGENTS.md` の表は「書き終える直前にも、ほかの worktree を `git worktree list` で見直す」と書き、守らせるものは「無し」である。ADR-0052 は初め 0048 で書かれ、main に入っていないほかの ADR と番号が重なって取り直した（PR #479 の commit「番号を取り直す」）。この文書を書いている間にも、取り合いの窓が見えた。読み始めたとき、ほかの worktree の最大の番号は 0053 だった。30 分ほどあとに番号を取ろうとすると、別の検討が 0054 のファイルを置いていた。
10. **番号を集める走査は軽い。** 手元にある origin の枝の控え（205 本。origin に今ある枝は 2 本で、残りはマージで消えた枝の古い控え）の木と、全部の worktree（走査したときは 12 個）の `docs/adr/` から番号を集めると、1.2 秒だった。追跡していないファイルも、worktree のフォルダを見れば拾える。worktree を持たない手元の枝は 24 本あり、今は独自の番号を持たない。
11. **一覧を読む機械は検査だけ。** 一覧を読むのは `tests/adr-index.sh` である。`tests/words-selftest.sh` は、一覧の行の形の例を `README.md` に書いて語の検査を試す（`tests/words.sh` に、一覧の行だけを外す扱いは無い）。image は `README.md` と `docs/adr/` を写さない。Chief Engineer の skill は、ADR を探すとき `docs/adr/` を grep すると書いていて、一覧を読めとは書いていない。
12. **1 日の本数。** 2026-11-22（UTC）の 1 日で、ADR の PR は 8 本出た。バージョンを切る間隔は、v0.0.11 から v0.0.12 が 7 日、v0.0.12 から v0.0.13 が 2 日だった。
13. **今の一覧は ADR の写しと少し違う。** 一覧の 52 行のうち 10 行は、タイトルが ADR の 1 行目と違う（古い語を今の語に直した行と、長い括弧を落とした行）。1 行（0002）は、状態のあとに「作業側の Space と tab は 0003 が覆した」の注を持つ。

モデル: 調べなかった（課題の状態も、状態を動かすコマンドの順も、自動で動く部品の順も変えない。番号を取る所は、1 つの鍵で直列にするだけである）。

## 前提（同意済み。番号）

1. 困りごとは、ADR の PR を並べて出すと、1 本のマージのたびに残りが止まり、オーナーの手が要ることである。
2. 衝突の元は ADR の一覧の 1 か所である。ADR-0046 で決めた `docs/adr/README.md` への引っ越しだけでは、同じ衝突が残る。
3. 番号の取り合いは衝突とは別の問題だが、同じ「並べて書けない」原因なので、この見直しに含める。
4. 何もしないと、Chief Engineer が同時に複数いる限り毎日起きる。
5. 既にあるもので済む部分がある。決定の記録は「1 件 1 ファイルにして一覧を作らない」形で同じ問題を片付けている。
6. 直すのは repo の文書と検査と手順である。Andon のしくみや新しい常駐の部品は足さない方向で考える。

1. **2026-11-22 範囲は、ADR の一覧と ADR の番号の 2 つにする。（オーナーが決めた）** ADR-0046 決めたこと 9 の一覧の決定を変えることを含む。
