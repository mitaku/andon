# ADR-0036: 役の名前を「人」から「オーナー」に改める（仕様・設計。2026-11-20）

- 状態: **決定（2026-11-20）**。オーナーが対話の中で「決めた」と言った。実装は「依頼書に切る案」のとおり別の課題（切るのは Chief of Staff）。覆すときは新しい ADR を書き、この行を「覆された → ADR-NNNN」に直す。小さな改めは「決めたこと」に下から足す。

## 問題（オーナーの言葉で。言い直しの段落）

オーナー（2026-11-20）: 「人　っていうのが結構無機質だからオーナーにしようかね」「Andon全体に広げましょう」

言い直し（オーナーが 2026-11-20 に「合っている」と答えた）: オーナーは、Andon の決まりの文やエージェントの返事で、自分が「人」と呼ばれることを無機質に感じている。11 月 9 日にも同じことを言ったが、そのときは文書 1 本の中だけを直し、用語集の役の名前は「人」のまま残った。skill も文書もコマンドの出力も用語集に従うので、今も「人の判断待ち」「人がマージ」と書かれ続けている。直したいのは役の名前そのもので、用語集の役を「オーナー」に改め、その役を指す「人」を Andon 全体で「オーナー」に替える。「外の人」「読む人」「1人」のように役を指さない「人」は替えない。変わるのは言葉だけで、しくみと識別子の動きは変えない。

対話の中でオーナーは、考え方をこう言った（2026-11-20）: 「『人』は役名ではないからね、リーダーや上司、社長などの役名にすることがシンプルと考えている」。役を、役の名前で呼ぶ。これがこの題の芯。

## 前提（同意済み。番号）

オーナーが 2026-11-20 に 1〜4 に同意した。

1. **相手は 1 人**: Andon の文で役としての「人」と書いている相手は、いつも 1 人で、セルの `andon.toml` の `owner` と同じ人。「オーナー」に替えても、指す相手が狭まって困る場面は無い。
2. **何もしないと**: 用語集の役の名前が「人」のままなので、エージェントは返事にも文書にも「人」と書き続ける。文書ごとに言い換えるやり方では、場所によって「人」と「オーナー」が混ざり続ける。だから用語集から直す。
3. **識別子は変えない**: `who: person`・`to: person`・`needs_human`・`human_touches` などの英語の識別子は、機械が読む約束で、変えると動いているセルの kanban と食い違う。替えるのは日本語の文だけ。
4. **届け方**: パッケージのバージョンアップで、用語集・skill・コマンドの出力は全セルに届く。skill を触る PR はオーナーがマージする。セルの側にある文（セルの repo の `AGENTS.md`・wiki・kanban に残る過去の依頼書と報告）はパッケージでは届かないので、扱いを別に決める。

### 反論で分かったこと（2026-11-20。別のコンテキストに設計案を壊させ、repo で証明できたものだけ）

- 対比の形でも役を指す「人」がある。`internal/process/process.go` は流れの定義の `person` を「人」と表に書き、`docs/process/*.md` の列になる。`docs/design.md` の冒頭には、1 文の中に対比の「人」と役の「人」が並ぶ所がある。`package/writing.md` の冒頭は「人に返す文」と「報告の人が読む部分」が同じ文にある。
- 「人がマージした」と「人の手直し」は同じ作りで決まる。`internal/issue/settle.go` は gate がマージした印が無ければ `by: person` とするだけで、だれがマージしたかは見ない。`internal/dispatcher/corrections.go` は bot でない commit とコメントを数える。
- 裸の「オーナー」が別の意味で使われている。CoS の skill の規約 10「持ち場の外はオーナーへ」は、ほかのプロジェクトの側を指す。同じ句にオーナーが 2 つ並ぶ所がある（`package/skills/retro/SKILL.md` の「人の文のセッションのオーナー」、`internal/retro/apply.go` の「Andon のオーナーへ伝えるか…を人が決める」）。裸で別の意味の行は、ほかに約 20 行ある（`docs/contract.md`・`docs/dispatcher.md`・`docs/operate.md`・`docs/design.md` §3.5・`SECURITY.md`・`internal/boot/owners.go`）。
- 文書を替えない案は成り立たない。`docs/process/*.md` は `process/` の YAML と `internal/process` からの生成物で、食い違うと `tests/process.sh` が落ちる。`tests/package.sh` は、CE の skill と `docs/design.md` と `docs/decisions.md` に同じ文を求める。
- 凍結した文書がある。`docs/vision.md` と図は「2026-11-07 の時点のもの」で書き直さずに残すと冒頭に書いてある。`docs/decisions.md` の表は凍結。`CHANGELOG.md` のバージョンの節は、バージョンを切ったときの記録。
- ADR の本文を替える案は、今日の決定とぶつかる。[ADR-0026](0026-pr-rules-for-outside-readers.md) 決めたこと 13 と [ADR-0033](0033-adr-inventory-and-slimming.md) の「やらないこと」は、畳む 6 本のほかの ADR の本文を当時の記録として残すとした。語の置き換えが凍結した記録に及ぶのは、2026-11-10 の語だけと限ってある。ADR の中には、当時の見出し `## 人に聞くこと` をバッククォートで写した所があり、替えると記録が事実と違ってしまう。
- gate が PR に書くコメントは、外の人に向けた文（`internal/gate/comment.go`。ADR-0026 決めたこと 9）。「人の判断が要る変更です」「人が見る変更」と書き、`tests/andon-gate.sh` が文面を固定している。
- 「人」が出てよい形の一覧で守る検査は、役の「人」をすり抜けさせる。「」の中を外すと節の名前の言及（「人の入口」など 48 か所）が通り、数え方の形は見出しの番号に当たり、「見出しの無い人の課題」「全部人」のような形も通る。
- 機械的に替えると「オーナー（オーナー）」になる所が 3 つある（用語集の委譲の項、`docs/design.md`、`docs/contract.md`）。
- 文面を固定する検査は、`tests/package.sh` に 16 行、`tests/andon-dispatcher.sh`・`andon-triage.sh`・`andon-retro-apply.sh`・`andon-measure.sh`・`schema.sh` に計 9 行、Go の検査に 12 か所ある。読む側で古い語と新しい語の両方を受ける必要があるのは、報告の見出しと課題の題の末尾の 2 つだけ。
- 量: 凍結した記録（ADR・決定の記録・`docs/vision.md` と図・`CHANGELOG.md`）を除くと、「人」を含む行は 186 ファイルに 1,536 行で、役を指すと仕分けた「人」は約 1,760 か所。凍結した記録は 113 ファイルに 1,511 行で、約 1,960 か所。gate は追加と削除の和で行を数え、`tests/**` を除く。

## 決めたこと（番号・日付・理由・捨てた案。あとから覆したら上書きせず下に足す）

1. **2026-11-20 ラインの中の人間の行いは「オーナー」と書く。**（オーナーが選んだ）
   ラインの中で頼む・決める・答える・マージする・直す・打つ人間は、前提 1 のとおりオーナー 1 人。その行いの主や相手を言う「人」は、機械や AI と並べて書いた所でも「オーナー」と書く。「人」のまま残すのは、数え方、熟語、ラインの外の人やだれでもよい人、文書の性質を言う「人が読む」「人用」。オーナーの発言の引用は替えない。
   理由: 例外が少なく、書く側が迷わない。「人がマージ」と「人の手直し」は同じ作りで決まるので、片方だけ替える線は引けない。
   捨てた案: 計測の語の「人の手直し」「人の介在」だけ「人」のまま残す（公開の repo では外の人のコメントも数に入る、という事実には正確だが、計測の表にだけ「人」が残る）。
   細部:

   | 今 | 直したあと |
   |---|---|
   | 人の判断待ち、人の決断、人に聞くこと | オーナーの判断待ち、オーナーの決断、オーナーに聞くこと |
   | 人がマージ、人の課題 | オーナーがマージ、オーナーの課題 |
   | 人への書き方、人への文 | オーナーへの書き方、オーナーへの文 |
   | 人が打った文、人の介在、人の手直し | オーナーが打った文、オーナーの介在、オーナーの手直し |
   | 流れの定義の表の列「機械・AI・人」 | 機械・AI・オーナー |
   | 引用の前の名札「人（2026-11-10）:」、出典の「人の発言」 | オーナー（2026-11-10）:、オーナーの発言 |
   | 人が読む Markdown、人用の文書 | そのまま |
   | 外の人、読む人、書く人、1人、個人 | そのまま |

   同じ文に「オーナーに返す文」と「人が読む部分」が並ぶ所は、同じ相手が 2 つの語に割れないように文を言い直す。
2. **2026-11-20 役の正式な名前は「セルのオーナー」で、文の中ではどこでも「オーナー」と書く。別の意味のオーナーには、必ず何のオーナーかを付ける。**（オーナーが選んだ。Chief Engineer の推奨は、書いた文では「セルのオーナー」、会話の返事だけ「オーナー」とする案だった）
   用語集の役の項の見出しを「セルのオーナー（略してオーナー）」にする。CoS・CE と同じ扱いで、正式な名前は用語集と、初めて説明するときだけ。裸の「オーナー」は役だけを指す。ファイル・repo・セッション・ほかのプロジェクトのオーナーは「ファイルのオーナー」のように書き、裸で別の意味になっている所は言い直す。
   理由（オーナー 2026-11-20）: 「セルで動いていて、CoSやCEが会話するのはエージェント同士か人（セルのオーナー）なのでオーナーで伝わるとは思いますけどね」。
   捨てた案: 役をいつも「セルのオーナー」と書く（紛れは無いが、約 1,760 か所が長くなる）／書いた文は「セルのオーナー」、会話の返事だけ「オーナー」（返事を文書に写すときに形が混ざる）／別の意味の方を「所有者」などに替える（2026-11-10 に、漢語の言い方をやめて「オーナー」に直すと決めたことを一部で戻す。ふだんカタカナで言う語を漢語に直さない決まりともぶつかる）。
   細部:
   - 用語集の役の項: 「**セルのオーナー**（略してオーナー）: 仕事を頼み、決断が要るところだけ決める人。セルに 1 人（`andon.toml` の `owner`）。ほかのもののオーナーを言うときは、『ファイルのオーナー』のように何のオーナーかを付ける。_避ける_: 人（この役を指すとき）、ユーザー、オペレーター」。
   - CoS の skill の規約 10「持ち場の外はオーナーへ」は、「持ち場の外は、その持ち場の CoS へ」に言い直す。手引きの見出しと対応表の行も同じ。
   - 同じ句にオーナーが 2 つ並ぶ所は言い直す。例: 「人の文のセッションのオーナー」は「オーナーが打った文は、そのセッションを持つ課題ごと」。
   - 「オーナー（人）」と書いた 3 か所（用語集の委譲の項、`docs/design.md`、`docs/contract.md`）は「オーナー」だけにする。
   - 裸で別の意味の約 20 行（「読んで分かった事実」の反論の段にある場所）は、何のオーナーかを付けるか、別の言い方にする。文面を検査が見ている行（`docs/contract.md` の Herdr App のラベルの行と `tests/schema.sh`、`internal/boot/owners.go` のログと `tests/image.sh`）は、検査と一緒に直す。
3. **2026-11-20 gate が PR に書く外向けのコメントでは、この役を「メンテナー」と書く。**（オーナーが選んだ）
   「人の判断が要る変更です」は「メンテナーの判断が要る変更です」、「人が見る変更」は「メンテナーが見る変更」、「外（人がマージする）」は「外（メンテナーがマージする）」にする。セルの中の文は「オーナー」のまま。
   理由（オーナー 2026-11-20）: 「『人』は役名ではないからね、リーダーや上司、社長などの役名にすることがシンプルと考えている、repoのオーナーは所有者という意味合いなのでオーナーじゃなくても適切なコミュニケーション上の役名になればいいですよ」。GitHub で PR を見てマージを決める役は、ふつうメンテナーと呼ばれる。
   捨てた案: 「オーナー」（語が 1 つで済むが、外の読み手は repo の所有者の意味で読む）／「人」のまま（役の名前でない）。
   細部:
   - 直す場所は `internal/gate/comment.go` の見出し・区分・範囲・理由の文と、文面を固定している `tests/andon-gate.sh`。commit status の説明文も同じ。
   - [ADR-0026](0026-pr-rules-for-outside-readers.md) 決めたこと 9 の例の文「人がマージする変更です」は、ADR-0026 の「決めたこと」に下から改めを足して直す。
   - 仮（Chief Engineer）: gate のコメントのほかの外向けの文（担当が書く PR の本文と commit、出所のトラッカーへ書き戻すコメント）でこの役を言うときも「メンテナー」と書く。決まりは担当の skill の PR の節と用語集の役の項に 1 行ずつ足す。オーナーが違うと言ったら直す。
4. **2026-11-20 替える範囲は repo の全部。過去の記録（ADR の本文と決定の記録）も、語だけ替える。**（オーナーが選んだ。Chief Engineer の推奨は、過去の記録は替えず、読み替えの 1 行を置く案だった）
   用語集・skill・コマンドの出力・コードのコメント・テスト・生きている文書に加えて、`docs/adr/` の本文と `docs/decisions/` と `docs/decisions.md` の表も替える。変えてよいのは語だけで、決定の中身・理由・捨てた案・番号・行の順は変えない。2026-11-10 の語の直し（[ADR-0013](0013-short-role-names-and-plain-japanese.md) 決めたこと 1）と同じ扱い。
   理由: 古い文書を読んだエージェントが「人」を真似ることが無くなり、読み手が読み替えをしなくて済む。
   捨てた案: 過去の記録は替えない（今日の ADR の棚卸しの決定とぶつからず、すぐ始められるが、ADR に「人」が約 1,960 か所残る）／用語集・skill・出力だけ替えて文書は替えない（`docs/process/*.md` が生成物で、`tests/package.sh` が skill と `docs/design.md` に同じ文を求めるので、成り立たない）。
   細部:
