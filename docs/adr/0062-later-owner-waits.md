# ADR-0062: オーナー待ちに「置いておく」の印を足し、行燈は今呼んでいるものだけで灯す（仕様・設計。2026-11-24）

- 状態: **決定（2026-11-24）**。オーナーが 2026-11-24 に「決めた」と答えた。実装は「依頼書に切る案」のとおり別の課題（切るのは Chief of Staff）。覆すときは新しい ADR を書く。
- 主題: 急がない判断が溜まって、行燈が灯り続けることを止める。オーナーに回す決断の種類（灯りの 5 種）は変えない。オーナー待ちに、今呼んでいるものと、置いてあるものの区別を足す。行燈は、呼んでいるものだけで灯す。区別を決める規則、印を書く口、`andon waiting` の出力、画面とダイジェストの見せ方、トリアージが Andon の skill の直しをオーナーに回す線、今あるオーナー待ちの移し方を決める。行燈が灯る条件を変える決定と、前の決定を改める決定を含む。
- 語は [design.md](../design.md) §0.1。機械が読む形の正は [contract.md](../contract.md) と `schema/`。この文書が足す約束は「決めたこと」に形を書き、実装の課題が写す（それまでは提案）。オーナー待ちの 3 種と `andon waiting` は [ADR-0042](0042-owner-waits-do-not-stop-the-line.md)、行燈が何で灯るかは [ADR-0043](0043-lamp-lights-on-owner-waits.md)、オーナーの課題の形は [ADR-0057](0057-owner-issue-decision-or-hand-work.md) が決めた。
- この文書で「呼んでいる」は、行燈を灯すオーナー待ちを指す。「置いてある」は、オーナーが見れば読めて答えられるが、行燈を灯さないオーナー待ちを指す。

## 問題（オーナーの言葉で。言い直しの段落）

オーナー（2026-11-24。1 つ目は、オーナーを呼ぶ判断ポイントについての発言の途中から写す）: 「…判断ポイントが明確（定義されている）が評価されているのはいいことですね、ちょっと今は崩している部分もありますがそこは大事にしていきたいです」「例えば今は Waiting on you の Decide がたまり過ぎている。その中にはすぐやらなくていいこともそこそこあるので、常に点灯しちゃってたりするんだよね。なので結構呼ばれてる感じがある」。

言い直し（オーナーが 2026-11-24 に、直す向きを答えた。「私待ちの作業に優先度をつけて灯すのかを判断しておくとよさそう」）。オーナーが大事にしたいのは、「オーナーを呼ぶのはこの種類の決断のときだけ」と定義してあり、行燈が灯ったら本当に今呼ばれている、という状態である。今は、決断の種類の定義は守られている。しかし、今答えないと何かが止まるかを見ずに、どの判断も同じ灯りにしている。そのため、急がない判断が溜まって行燈が消えず、呼ばれている感じだけが続く。望んでいるのは、判断ポイントの定義は崩さずに、急がないものは呼ばずに置いておけて、行燈は今オーナーを待っているものがあるときだけ灯る形である。

モデル: 調べなかった（読むだけの command の数え方と、課題の予約キーを 2 つと、判断を作る command の旗と、トリアージの判定の線を変える。課題の状態の定義、状態を動かす command の順、dispatcher と gate とレビューの順、役の間のやりとりは変えない。command が新しく断るのは旗とキーの形と打った端末だけで、課題の状態を見て断る条件は足さない）

### 作る側

    理由: 今の行き詰まりは、急ぐかどうかをだれも決めていないことから来ている。skill の文だけで頼むと、書かれないまま今と同じに全部が灯る。作る command が形で断れば、作るたびに 1 回は考える（[ADR-0057](0057-owner-issue-decision-or-hand-work.md) 決めたこと 2 の「作る側に言い切らせる」と同じ考え）。
