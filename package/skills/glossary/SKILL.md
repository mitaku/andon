# Andon の用語集

- **役と部品の語はここにある語だけを使う**。人やエージェントが「避ける」の語を使ったら、正しい語を示し返す。
- 語は日本語で呼ぶ。役の名前は英語のまま（Chief Engineer・Chief of Staff・dispatcher）か一般のカタカナ（レビュアー）。
- 人への書き方と語の決まり（文の中の略称・カタカナのまま言う語・訳語を作らない）は `/opt/andon/writing.md` に従う。
- 見出しの括弧は識別子（CLI・ファイル・ラベル）に使う英語。
- 業務の言葉（各案件の顧客・製品の語）はここに書かない。案件ごとに用語集を持つ（書き手は Chief Engineer）。

## 工場と場所

**Andon**（andon）:
工場そのもの。構造の名前。部品の名前には使わない。
_避ける_: 工場の部品を「アンドン」と呼ぶこと

**セル**（cell）:
案件（信頼境界）ごとに1つ立てる長寿命のコンテナと、その設定 repo（`<slug>-cell`）。手元にもクラウドにも立つ。
_避ける_: 環境、ワークスペース、サーバー

**パッケージ**（package）:
Andon からセルに配るもの一式: base image と `/opt/andon/`（command・skill・プロファイル・フック・ゲートの条件表・環境メモ）。
_避ける_: 雛形、テンプレート（セルの repo の雛形は別のもの）

**プロジェクト**（project）:
セルの中の持ち場1つ（`projects/<slug>/`）。Chief of Staff が1人、台帳が1つある。1つ以上のリポジトリを持つ。
_避ける_: リポジトリ（プロジェクトとは別のもの）、スペース

**リポジトリ**（repo）:
git のリポジトリ1つ。`host/owner/repo` の形で呼ぶ。
_避ける_: プロジェクト

**worktree**:
課題ごとに切る作業用の checkout。branch と一対一。
_避ける_: clone、作業フォルダ

**指揮側／作業側**（control／work）:
セルの中の2段。指揮側＝人・Chief of Staff・dispatcher・ゲート・台帳・wiki。作業側＝担当・レビュアー（別のマシンでもよい）。

## 役

**人**:
仕事を頼み、決断が要るところだけ決める人。
_避ける_: ユーザー、オペレーター

**Chief Engineer**（chief-engineer。略して CE）:
人と仕様・設計を対話し、決めたことを文書にしてラインへ渡す役。実装も課題を切ることもしない。1プロジェクトに1題。出典はトヨタ生産方式の主査。
_避ける_: アーキテクト、設計担当、PM

**Chief of Staff**（chief-of-staff。略して CoS）:
ラインを回す役。文書と人の依頼を依頼書に切り、担当を起動し、検収し、振り返る。人と設計の対話はしない。プロジェクトに1人。
_避ける_: コーディネーター、リーダー、オーケストレーター

**担当**（worker）:
1つの課題のために起動するエージェント。自分の worktree の中だけで働き、報告を書いて終わる。
_避ける_: 担当エージェント、task agent、thread、coder

**レビュアー**（reviewer）:
実装と別ブランドのモデルで、書いていない目で commit を読み、指摘を重さつきで返す。直さず、マージの可否も言わない。
_避ける_: 検収者、承認者

**dispatcher**:
セルに1つ常駐するプログラム。台帳と端末を周期で回り、通知を届け、決まった次の工程を起動する。判断はしない。出典は水すまし（water spider）。
_避ける_: news、runner、bot

**エージェント**（agent）:
hc の端末1つで動くコーディングエージェント（Claude Code・Codex など）。

**サブエージェント**（subagent）:
1つのエージェントのセッションの中で動く助手。hc からは見えない。読むだけで、その turn のうちに返る仕事に限る。
_避ける_: 子エージェント（hc の子の端末と混ざる）

**プロファイル**（profile）:
エージェントの起動のしかた（CLI・モデル・effort）の名前。hc の template が中身を持つ（`chief-of-staff`・`chief-engineer`・`claude`・`sonnet`・`fable`・`codex`・`codex-review`・`claude-review`）。作る・変えるのは人だけ。
_避ける_: モデル（プロファイルの中身の一部）

## 仕事

**ライン**（line）:
課題が依頼書からマージまで流れる工程の列（＝インナーループ）。「ラインそのものの変更」はゲートの条件表・skill・設定・フックの変更。

**台帳**（ledger）:
プロジェクトごとの課題・問い・ルーチン・履歴のファイル群（`kanban/`）。書くのは台帳の CLI（今は `kanban`）だけ。
_避ける_: バックログ、トラッカー、ボード（ボードは台帳を見る画面）

包含の図（課題が作業を内包する）:

```
課題（issue）A-0012 「ログインが落ちる」      ← 台帳のカード。依頼書: 解決すべき問題・完了条件
├─ 作業（task）1: 再現テストを足す。終了条件: 落ちるのを確かめた
├─ 作業（task）2: 原因の module を直す。終了条件: テスト green
└─ 作業（task）3: 横展開で同じ呼び方を探す。終了条件: grep を読み切った
```

**課題**（issue）:
台帳のカード1枚（`issues/<id>/`・`issue.yaml`・`andon issue`）。何が困っていて、何が出れば解けたか（解決すべき問題）と完了条件を持つ。どう直すかは持たない。かんばん。プロジェクトの外では `<slug>/<id>` と呼ぶ。人へ書くときの形は `/opt/andon/writing.md` の番号の決まりに従う。置くのは Chief of Staff（依頼書）。
_避ける_: タスク（古い文書では課題の意味。作業と混ざる）、チケット、job、Issue（外部トラッカーのもの。指すときは「<トラッカー名> の Issue」）

**作業**（task）:
担当が計画で課題を分けた単位。1つの課題に1つ以上。報告の `## 計画` に終了条件つきで1行ずつ書く。台帳には乗らない（識別子は無い）。
_避ける_: タスク、サブタスク（台帳の子の課題と混ざる）、ステップ

**依頼書**（brief）:
課題の文書（`brief.md`）。解決すべき問題・なぜ・完了条件・横展開・守ること・Settings。人と AI が読む。Settings の正は `issue.yaml` の項目。
_避ける_: 指示書、プロンプト

**完了条件／終了条件**:
完了条件＝課題が解けたと言える状態（依頼書の欄。Chief of Staff が書き、担当は書き換えない）。終了条件＝作業をいつ終えるか（計画。担当が置く。中止の条件も入る）。
_避ける_: 2つを混ぜること（作業が終わった＝課題が解けた、にしない）

**調べる課題／直す課題**（survey／fix）:
課題の型。調べる課題は候補の一覧が成果で、直さず PR を出さない（`deliverable: candidates`）。直す課題は PR が成果（`deliverable: pr`。既定）。決めるのは Chief Engineer の仕事で、型の名前を付けない。
_避ける_: 調査課題、research task

**deliverable**:
課題の成果の形。`issue.yaml` の予約キー（`pr`／`candidates`）。書くのは Chief of Staff。依頼書の Settings の `Deliverable:` はその写し。

**候補**（candidate）:
調べて見つけた、直すかもしれないが決めていないもの1つ。一覧は `library/candidates.json`（`id`・何をどこでどう直すか・範囲の中か〈`in_scope`〉）。担当が書き、Chief of Staff が切る・答える。
_避ける_: 指摘（レビュアーの語。直す前提）、課題（台帳のカード。候補はまだ決めていない）

**横展開**:
直す課題の担当が、指されたものと同じ種類をほかにも探すこと。理解の工程で既定として探し、範囲の中は直し、外は候補に残し、何を・どこまで・どう探したかを報告に書く。
_避ける_: これを「横展」と呼ぶこと（横展は方針の語で、1か所の学びを全セルへ広げること）

**報告**（report）:
担当が課題ごとに書く結果（`report.md`。次の一手は `## Next`、残す学びは `## Remember` と `For AGENTS.md:`）。機械向けの部分は JSON。
_避ける_: 完了報告、ログ

**問い**（question）:
人の決断を求める1通。決断の種類・事実・理由・選択肢・推奨案・あと何問。1通で答えられる形にする。範囲の問い（`kind: scope`。候補のどれを直すか）だけは Chief of Staff 宛てで、灯りではない。
_避ける_: 確認事項

**推奨案**:
問いに添える、出した側が勧める選択肢。「はい」で通る形にする。
_避ける_: 推し

**通知**（notification）:
dispatcher が Chief of Staff へ届ける機械の合図（報告が書かれた・レビューに入った・問いが来た・担当が止まった…）。`<news>` の文で届く。人は呼ばない。人の依頼ではない。
_避ける_: 知らせ、news、メッセージ

**ルーチン**（routine）:
台帳にある定期の仕事（振り返り・トリアージ・見回り）。トリガーが来るたびに台帳に課題を1件足す。
_避ける_: automation、cron（cron は時刻の書き方の名前としてだけ）

**トリアージ**（triage）:
報告の「次にやること」などを集めて、課題に切る・捨てる・寝かせるを決める手。

**振り返り**（retro）:
アウターループのルーチン。記録を読んでつまずきを拾い、環境を直す PR を出す。出典は反省（hansei）、改善の PR はカイゼン。

**インナーループ／アウターループ**（inner／outer loop）:
内側＝ライン。外側＝振り返り。合わせてダブルループ。

**library**:
課題が作ったファイルの置き場（`issues/<id>/library/`）。担当が worktree の外に書いてよい唯一の場所で、機械向けの JSON もここに置く。
_避ける_: 成果物フォルダ

**ステータス**（status）:
課題がどの列にいるか（`todo`・`queued`・`doing`・`review`・`done`）。
_避ける_: 状態（エージェントの状態と混ざる）

## 流れと状態の定義

Chief of Staff の定常の仕事と、ものの状態の移り方を、andon の repo の `process/` に YAML で書いたもの。人が読む表と図は `docs/process/` に生成する。

**ワークストリーム**（workstream）:
Chief of Staff の定常の仕事の流れ1本。きっかけと手順（だれが・何を受けて・何を出すか）を持つ。定義は `process/workstreams/<name>.yaml`。手順はワークストリームの中の1つで、担当の作業とは別のもの。
_避ける_: 業務フロー、プロセス（定義の置き場の名としてだけ）

ワークストリームは次の8本。日本語の名に英語を併記する（英語の小文字が `name`）。

| 名 | きっかけ | 目的 |
|---|---|---|
| 受付（Intake） | 人の依頼 | 依頼と Chief Engineer の文書を課題に切る |
| 仕分け（Triage） | 外のお知らせと間隔 | 溜まったものを課題に切る・閉じる・人へ回す |
| 起動（Launch） | 通知（`ready`） | 担当を起こす |
| 見守り（Watch） | 間隔 | 担当の進みを見て、ズレたときだけ手を打つ |
| 受け取り（Receive） | 報告とゲートの合否 | 検収・差し戻し・片付け |
| 取り次ぎ（Relay） | 問い | 人へ1問ずつ渡して答えを返す |
| 結果を見る（Observe） | 見る日 | 価値の仮説を確かめる |
| ふりかえり（Retrospective） | 課題の終わりと週1回 | つまずきを拾い、環境を直す |

**ステートマシン**（state machine）:
もの1つ（課題・担当の端末・通知の配達・レビュアーの起動・ゲートとマージ・人のマージの見張り・片付けのあとの仕事・外のお知らせ）の状態と移り方の定義。定義は `process/states/<name>.yaml`。課題がどの列にいるかはステータス（台帳）で、課題のステートマシンはその上に Andon の工程を足す。
_避ける_: 状態遷移図（図は生成物の一部）

**きっかけ表**（trigger table）:
全ワークストリームのきっかけ（`triggers[]`）のうち、間隔で回るものの一覧。dispatcher の1巡は、このうち時が来た行を打つだけ。
_避ける_: cron 表、スケジュール

**見込み**（estimate）:
課題の大きさの目安（小 30分・中 60分・大 120分。待ちを除いた実働）。`issue.yaml` の予約キー。書くのは Chief of Staff。上限ではない。見込みの 1・2・4 倍を超えると dispatcher が Chief of Staff にだけ通知する。
_避ける_: 見積もり、期限、上限

**留守**:
Chief of Staff の端末が無い間。dispatcher は通知を配る段だけ止め、拾う・記録する・コマンドを打つ段は回して、通知を待ちに積む。戻った最初の通知の先頭に「留守の間に N 件」の1行が付く。
_避ける_: 離席（人が画面の前にいないこと。別のもの）

## 決断とブレーキ

**灯り**（andon light）:
人の決断待ち。灯りは呼び出し（事業・利用者・約束）と定位置停止（不可逆・ラインそのものの変更）の2つで、つくのは次の決断だけ: 事業（何を作るか）・利用者・約束（外との契約や公開）・不可逆（push 先・削除・本番・資格情報）・ラインそのものの変更（レベル C）。
_避ける_: 承認ポイント、要対応

**「Needs you」**:
エージェントが人を待っている状態（hc の blocked）。課題のステータスではない。画面の表示のまま呼ぶ。

**委譲**（delegation）:
オーナー（人）が Chief of Staff（と dispatcher・担当）に任せた範囲。プロジェクトごとのファイルで持ち、人だけが書く。範囲の中は聞かずに進める。「何を作るか」は委譲できない。

**ゲート**（gate）:
PR をマージしてよいかの決定式。条件表（JSON）を読み、`approve`／`fix`／`needs_human` を返す。Markdown を読まない。
_避ける_: merge-gate

**レベル A／B／C**（tier）:
ゲートが変更ごとに決める段階。A＝テストが通れば自動マージ、B＝独立レビューつきで自動マージ、C＝人がマージ（ラインそのものの変更・不可逆なもの）。
_避ける_: 段

**検査**（checks）:
決まった検査（型・lint・テスト）。担当の commit は全部通す。
_避ける_: CI（検査を走らせる場所の1つ）

**レビュー**（review）:
レビュアーが commit を読む工程。観点はリポジトリの `REVIEW.md`。指摘の機械向けの形は `findings.json`。
_避ける_: 検収

**検収**:
Chief of Staff が担当の結果を実物（PR・checks・レビューの commit）で確かめること。

## 方針の語

文書と skill の文で使う。括弧は英名。

- **自工程完結**（built-in quality）: 自分の工程で品質を作り込み、不良を後工程に渡さない。担当の工程の方針。
- **自働化**（autonomation）: 異常なら止まって人を呼ぶ。ゲートの方針。
- **ポカヨケ**（poka-yoke）: 間違えられない作りにする（`gh pr merge` を打てない・HEAD の照合）。
- **現地現物**（go and see）: 言われた結果を信じず実物を読む。検収と振り返りの方針。
- **平準化**（heijunka）: 並行の上限で山と谷を作らない。
- **横展**（yokoten）: 1か所の学びを、パッケージの版上げで全セルへ広げる。

## 外部の部品

**hc**:
エージェント用の永続する端末。マシンをまたいで端末とエージェントを動かす。文の中でも hc と書く。
_避ける_: 端末の土台（作った語）

**ボード**:
全セルの自分待ちを1画面で見る人の Interface（Web ボードと画面の mod）。台帳と端末のラベルを読む。

## 仮設の語（2026-11 以前）

前の工場の文書や台帳を読むときの対応。Andon の文ではこの左の語を使わない。

| 仮設の語 | Andon の語 |
|---|---|
| yard（案件ごとのコンテナと repo） | セル（`andon`） |
| 建屋（plant。2026-11-06 までの Andon の語。ADR と決定の記録に残る） | セル（`cell`） |
| `yard <sub>`（CLI） | `andon <sub>` |
| コーディネーター（coordinator） | Chief of Staff（`chief-of-staff`） |
| 担当エージェント（task agent） | 担当（`worker`） |
| yard news（通知の係） | dispatcher（`andon dispatcher`） |
| 知らせ | 通知 |
| 段 A／B／C | レベル A／B／C |
| 来歴・道しるべ・推し | 履歴・指針・推奨案 |
| deck（仮設の台帳の CLI） | 台帳の CLI（`kanban`） |
| タスク（台帳のカード。`tasks/<id>/`・`task.yaml`・`andon task`） | 課題（`issue`。`issues/<id>/`・`issue.yaml`・`andon issue`） |
| flightdeck（Web ボード・画面の mod） | ボード |
| （無い。コーディネーターが兼ねていた） | Chief Engineer（`chief-engineer`） |
