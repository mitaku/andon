# Andon の用語集

- **ここにある語だけを使う**。人やエージェントが「避ける」の語を使ったら、正しい語を示し返す。
- 語は日本語で呼ぶ。ただし作った訳語は使わず、ふだん口にする言い方か、もともとある日本語にする。役の名前は英語のまま（Chief Engineer・Chief of Staff・dispatcher）か一般のカタカナ（レビュアー）。
- 見出しの括弧は識別子（CLI・ファイル・ラベル）に使う英語。
- 業務の言葉（各案件の顧客・製品の語）はここに書かない。案件ごとに用語集を持つ（書き手は Chief Engineer）。

## 工場と場所

**Andon**（andon）:
工場そのもの。構造の名前。部品の名前には使わない。
_避ける_: 工場の部品を「アンドン」と呼ぶこと

**建屋**（plant）:
案件（信頼境界）ごとに1つ立てる長寿命のコンテナと、その設定 repo（`andon-<slug>`）。手元にもクラウドにも立つ。
_避ける_: 環境、ワークスペース、サーバー

**パッケージ**（package）:
Andon から建屋に配るもの一式: base image と `/opt/andon/`（command・skill・プロファイル・フック・ゲートの条件表・環境メモ）。
_避ける_: 雛形、テンプレート（建屋の repo の雛形は別のもの）

**プロジェクト**（project）:
建屋の中の持ち場1つ（`projects/<slug>/`）。Chief of Staff が1人、台帳が1つある。1つ以上のリポジトリを持つ。
_避ける_: リポジトリ（プロジェクトとは別のもの）、スペース

**リポジトリ**（repo）:
git のリポジトリ1つ。`host/owner/repo` の形で呼ぶ。
_避ける_: プロジェクト

**worktree**:
タスクごとに切る作業用の checkout。branch と一対一。
_避ける_: clone、作業フォルダ

**指揮側／作業側**（control／work）:
建屋の中の2段。指揮側＝人・Chief of Staff・dispatcher・ゲート・台帳・wiki。作業側＝担当・レビュアー（別のマシンでもよい）。

## 役

**人**:
仕事を頼み、判断が要るところだけ決める人。
_避ける_: ユーザー、オペレーター

**Chief Engineer**（chief-engineer）:
人と仕様・設計を対話し、決めたことを文書にしてラインへ渡す役。実装もタスク切りもしない。1プロジェクトに1題。出典はトヨタ生産方式の主査。
_避ける_: アーキテクト、設計担当、PM

**Chief of Staff**（chief-of-staff。略して CoS）:
ラインを回す役。文書と人の依頼を依頼書に切り、担当を起こし、検収し、振り返る。人と設計の対話はしない。プロジェクトに1人。
_避ける_: コーディネーター、リーダー、オーケストレーター

**担当**（worker）:
1つのタスクのために起きるエージェント。自分の worktree の中だけで働き、報告を書いて終わる。
_避ける_: 担当エージェント、task agent、thread、coder

**レビュアー**（reviewer）:
実装と別ブランドのモデルで、書いていない目で commit を読み、指摘を重さつきで返す。直さず、マージの可否も言わない。
_避ける_: 検収者、承認者

**dispatcher**:
建屋に1つ常駐するプログラム。台帳と端末を周期で回り、通知を届け、決まった次の工程を起こす。判断はしない。出典は水すまし（water spider）。
_避ける_: news、runner、bot

**エージェント**（agent）:
端末の土台の端末1つで動くコーディングエージェント（Claude Code・Codex など）。

**サブエージェント**（subagent）:
1つのエージェントのセッションの中で動く助手。端末の土台からは見えない。読むだけで、その turn のうちに返る仕事に限る。
_避ける_: 子エージェント（端末の土台の子の端末と混ざる）

**プロファイル**（profile）:
エージェントの起こし方（CLI・モデル・effort）の名前。端末の土台の template が中身を持つ（`chief-of-staff`・`chief-engineer`・`claude`・`sonnet`・`fable`・`codex`・`codex-review`・`claude-review`）。作る・変えるのは人だけ。
_避ける_: モデル（プロファイルの中身の一部）

## 仕事

**ライン**（line）:
タスクが依頼書からマージまで流れる工程の列（＝インナーループ）。「ラインそのものの変更」はゲートの条件表・skill・設定・フックの変更。

**台帳**（ledger）:
プロジェクトごとのタスク・問い・ルーチン・履歴のファイル群（`.flightdeck/`）。書くのは台帳の CLI（今は `deck`）だけ。
_避ける_: バックログ、トラッカー、ボード（ボードは台帳を見る画面）

**タスク**（work item）:
台帳のカード1枚（`tasks/<id>/`）。かんばん。プロジェクトの外では `<slug>/<id>` と呼ぶ。人へ書くときは「番号（題）」。
_避ける_: チケット、issue、job

**依頼書**（brief）:
タスクの文書（`brief.md`）。背景・完了条件・守ること・Settings。人と AI が読む。Settings の正は `task.yaml` の項目。
_避ける_: 指示書、プロンプト

**報告**（report）:
担当がタスクごとに書く結果（`report.md`。次の一手は `## Next`、残す学びは `## Remember` と `For AGENTS.md:`）。機械向けの部分は JSON。
_避ける_: 完了報告、ログ

**問い**（question）:
人の判断を求める1通。判断の種類・事実・理由・選択肢・推奨案・あと何問。1通で答えられる形にする。
_避ける_: 確認事項

**推奨案**:
問いに添える、出した側が勧める選択肢。「はい」で通る形にする。
_避ける_: 推し

**通知**（notification）:
dispatcher が Chief of Staff へ届ける機械の合図（報告が書かれた・レビューに入った・問いが来た・担当が止まった…）。`<news>` の文で届く。人は呼ばない。人の依頼ではない。
_避ける_: 知らせ、news、メッセージ

**ルーチン**（routine）:
台帳にある定期の仕事（振り返り・トリアージ・見回り）。トリガーが来るたびに台帳にタスクを1件足す。
_避ける_: automation、cron（cron は時刻の書き方の名前としてだけ）

**トリアージ**（triage）:
報告の「次にやること」などを集めて、タスクに切る・捨てる・寝かせるを決める手。

**振り返り**（retro）:
アウターループのルーチン。記録を読んでつまずきを拾い、環境を直す PR を出す。出典は反省（hansei）、改善の PR はカイゼン。

**インナーループ／アウターループ**（inner／outer loop）:
内側＝ライン。外側＝振り返り。合わせてダブルループ。

**library**:
タスクが作ったファイルの置き場（`tasks/<id>/library/`）。担当が worktree の外に書いてよい唯一の場所で、機械向けの JSON もここに置く。
_避ける_: 成果物フォルダ、artifacts

**ステータス**（status）:
タスクがどの列にいるか（`todo`・`queued`・`doing`・`review`・`done`）。
_避ける_: 状態（エージェントの状態と混ざる）

## 判断とブレーキ

**灯り**（andon light）:
人の判断待ち。つくのは5種だけ: 事業（何を作るか）・利用者・約束（外との契約や公開）・不可逆（push 先・削除・本番・資格情報）・ラインそのものの変更（レベル C）。
_避ける_: 承認ポイント、要対応

**「Needs you」**:
エージェントが人を待っている状態（端末の土台の blocked）。タスクのステータスではない。画面の表示のまま呼ぶ。

**委譲**（delegation）:
オーナー（人）が Chief of Staff（と dispatcher・担当）に任せた範囲。プロジェクトごとのファイルで持ち、人だけが書く。範囲の中は聞かずに進める。「何を作るか」は委譲できない。

**ゲート**（gate）:
PR をマージしてよいかの決定式。条件表（JSON）を読み、`approve`／`fix`／`needs_human` を返す。Markdown を読まない。
_避ける_: merge-gate

**レベル A／B／C**（tier）:
ゲートが変更ごとに決める段階。A＝テストが通れば自動マージ、B＝独立レビューつきで自動マージ、C＝人がマージ（ラインそのものの変更・不可逆なもの）。
_避ける_: 段

**検査**（checks）:
決まった検査（型・lint・テスト）。担当の commit は全部通す。
_避ける_: CI（検査を走らせる場所の1つ）

**レビュー**（review）:
レビュアーが commit を読む工程。観点はリポジトリの `REVIEW.md`。指摘の機械向けの形は `findings.json`。
_避ける_: 検収

**検収**:
Chief of Staff が担当の結果を実物（PR・checks・レビューの commit）で確かめること。

## 方針の語

文書と skill の文で使う。括弧は英名。

- **自工程完結**（built-in quality）: 自分の工程で品質を作り込み、不良を後工程に渡さない。担当の工程の方針。
- **自働化**（autonomation）: 異常なら止まって人を呼ぶ。ゲートの方針。
- **ポカヨケ**（poka-yoke）: 間違えられない作りにする（`gh pr merge` を打てない・HEAD の照合）。
- **現地現物**（go and see）: 言われた結果を信じず実物を読む。検収と振り返りの方針。
- **平準化**（heijunka）: 並行の上限で山と谷を作らない。
- **横展**（yokoten）: 1か所の学びを、パッケージの版上げで全建屋へ広げる。

## 外部の部品

**hc**（端末の土台）:
エージェント用の永続する端末。マシンをまたいで端末とエージェントを動かす。

**ボード**:
全建屋の自分待ちを1画面で見る人の Interface（Web ボードと画面の mod）。台帳と端末のラベルを読む。

## 仮設の語（2026-11 以前）

前の工場の文書や台帳を読むときの対応。Andon の文ではこの左の語を使わない。

| 仮設の語 | Andon の語 |
|---|---|
| yard（案件ごとのコンテナと repo） | 建屋（`andon`） |
| `yard <sub>`（CLI） | `andon <sub>` |
| コーディネーター（coordinator） | Chief of Staff（`chief-of-staff`） |
| 担当エージェント（task agent） | 担当（`worker`） |
| yard news（通知の係） | dispatcher（`andon dispatcher`） |
| 知らせ | 通知 |
| 段 A／B／C | レベル A／B／C |
| 来歴・道しるべ・推し | 履歴・指針・推奨案 |
| deck（台帳の CLI） | 台帳の CLI（移したら `kanban`） |
| flightdeck（Web ボード・画面の mod） | ボード |
| （無い。コーディネーターが兼ねていた） | Chief Engineer（`chief-engineer`） |
