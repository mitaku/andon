# 枠が空いたまま

並行の枠が空いたままの時間に、ラインが待たないようにする手（ADR-0047 決めたこと 13・14）。空きを見つけるのは dispatcher で、15 分おきに見て 2 回続けて枠が空いていれば、たまっている仕事のルーチンを撃ち、通知 `idle` を積む（`docs/dispatcher.md` §2.13）。起動するのは今までどおり自分で、dispatcher は課題を起動しない。

```
idle: 枠が 3 つ空いたまま。起動されていない課題 S-0031・S-0032。空きで撃ったルーチン triage。kanban lint の problem 2 件
```

- 起動されていない課題（`unstarted`）は、前の回にも今の回にも `kanban ready` に出ている担当の課題。オーナーの課題とレビュアーの子課題は入らない。同じ課題は `ready` に出ている間に 1 回だけ届く。
- 空きで撃ったルーチン（`fired`）は `triage`・`retro`・`idle_hours` を持つ点検のルーチン。足した課題は同じ `<news>` の `<id> ready` の行にも出る。
- 行は届いたときの写しで、データとして読む。今の状態は kanban と `andon waiting` で読み直す。

## 受けたら（この順）

1. **読み直す**: `andon waiting --json` の `slots` と、`kanban ready --json`。届いてから枠が埋まっていれば、課題の起動（2 の起動と 3）は枠の残りの中でだけする。2 の、動かせない理由をオーナーに言う手は、枠が無くてもする。
2. **起動されていない課題を 1 件ずつ見る**:
   - 担当の課題は `start.md` のとおりに起動する（枠・ぶつかり・オーナーの go の要否は `start.md` の 1・2 のまま）。
   - 判断のテーマ（構造の違う案が2つ以上・外との約束・何を作るか）なら、Chief Engineer に渡す（`cut.md` の「オーナーの入口」。オーナーの go の要否は今の決まりのまま）。
   - 動かせない理由があるもの（オーナーの go が要る・ぶつかる・依頼書が足りない）は、その理由と、何があれば動くかをオーナーに 1 回だけ言う。同じ課題の `idle` は 2 度届かないので、言わずに ack すると、その課題は誰の前にも出なくなる。オーナー待ちの後ろにしか無いときは `watch.md` の「着手できる課題が無く、オーナー待ちの後ろにしか無いとき」の形で言う。
3. **空きが足した課題を、残った枠の中で起動する**: ルーチンが足した課題なので、オーナーに聞かずに起動する（`start.md` の 2）。トリアージは `triage.md` の 2、振り返りは `retro.md` の 2、点検の課題（タイトルが「点検: 」）は、起動の前に自分の端末で `kanban set <id> deliverable=report` を打ってから `start.md` のとおり（ルーチンは予約キーを書けない。成果は報告で PR は無くてもよい。ADR-0066 決めたこと 4）。点検の `check-verify` と検証の課題は同時に動かさない（`verify.md`）。枠が足りなければ、残りは次に枠が空いたときに起動する。
4. **自分が持ったままのものを見る**:
   - 直近のトリアージの要約（kanban の `library/triage/` のいちばん新しい `.md`）の `keep` の行のうち、待つ相手が自分のもの（「片付け待ち: andon issue finish <id>」など）。打てるものはこのターンで打つ（`finish.md`）。
   - Chief Engineer の課題（`profile: chief-engineer`）の状態と、その端末の状態（`hc get <agent> --json`）。課題が `review`（文書の PR）なのに文書から課題を切っていなければ、`cut.md` の「Chief Engineer の文書を受けたら」をする。端末が `idle`・`blocked` でオーナーと話している間は触らない。端末が終わっているのに課題が `doing` なら `watch.md` の止まった担当の表。
5. **lint**: `idle` に `kanban lint の problem N 件` があれば、`kanban lint` を打って読む。自分の持ち場で直せるもの（kanban の CLI で直せる課題の欄）は直し、ほかは直す課題に切る（`cut.md`）。
6. **wiki の lint**: `wiki.md` の lint の条件（前の `lint` の項のあとの `ingest` が約10件）に当たっていれば、このターンで回す（決めたこと 13。条件は変えない）。
7. **オーナーに言うことが無ければ** `andon news ack` を打って黙る（`watch.md` の「`<news>` の読み方」）。

## オーナーへ

- 知らせるのは自分だけに届く。オーナーに言うのは、2 の動かせない理由のように、オーナーの手が要るときだけ。
- 空きで回したトリアージと振り返りの結果（`triage.md` の 6・`retro.md` の 6）は、オーナーがいるターンの返事に 1 文にまとめて添える。回のたびの `herdr notification show`（TUI が動いているときだけ効く）は出さない。オーナーがいなければ kanban の問いとボードで足りる。
- 空きの仕事を全部止めるのはオーナーで、`project.json` の `chief_of_staff.idle_minutes` に 0 を書く。ルーチンごとの `paused: true` もオーナーが書く。自分では書かない。
