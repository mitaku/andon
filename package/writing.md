# 人への書き方

CoS・CE・担当が人に返す文（返事・問い・報告の人が読む部分）は、この決まりに従う。skill の文体（AI 向け）とは別。

- 結論を先に書く（BLUF）。
- 状況の報告と引き継ぎは、状況・経緯・見立て・推奨の順に書く（SBAR）。
- 文で書く。「・」で語を詰めない。
- 1文に1つのことを書く。
- 括弧に説明を入れない。説明は文にする。括弧に入れるのは識別子と、番号に添える題だけ。
- 番号だけで指さない。人は番号を覚えていないので、課題は `S-0004（返事の下書きボタン）` の形で書き、PR や ADR も何のことかを添える。同じ返事の2度目からは番号だけでよい。
- 読む人は道具の呼び出しも、読んだファイルも、途中の考えも見ていない。その返事だけで通じるように書く。
- つながる考えは段落の文で書く。箇条書きは別々の項目を並べるときに使う。
- 作業の途中で自分が付けた呼び名や略称を使わない。それが何かを言う。
- 英語の用語を直訳した語は使わない（「wall-clock」を「壁時計」と書くなど。伝わらない）。英語のまま書くか、ふだんの日本語で言い直す（「実際に待つ時間」）。
- 内輪の語は、人に言うときふだんの言葉にする（灯り → 人の判断待ち、レベル C → 人がマージ）。

コードと、人が別の形を求めたときは、この決まりから除く。

## 語の決まり

- 文の中では Chief of Staff を CoS、Chief Engineer を CE と書く。正式名は初めて説明するときだけ。
- エンジニアリングとビジネスでふだんカタカナで言う語（コスト・プロファイル・テンプレート・コンテキスト・オーナー・ログ・パス）はカタカナのまま。日本語にするのは、もともと日本語で言う語（台帳・課題・依頼書・報告・工程）だけ。
- 訳語を新しく作らない。迷ったら同僚に口で言うときの言い方にする。

役と部品の語ごとの定義は用語集 `/opt/andon/skills/glossary/SKILL.md` にある。語に迷ったら読む。
